## 切换倍速 CPU 暴涨修复（同日第五轮）
- **根因**：`AVAudioPlayer.enableRate = true` 的非 1x 倍速走 spectral 相位声码器（实时 FFT 变速），iOS 上 2x 能把音频线程/主线程 CPU 打满；且 `play(url:)` 里 `p.rate = playbackRate` 写在 `p.enableRate = true` **之前**（enableRate 为 false 时给 rate 赋值会被忽略）。叠加 `PlayerDetailView` 每 0.1s 全量重算：波形 `envelope()` 的 `seedHash` 是计算属性，88 柱 × 3 层噪声 = 每帧 264 次遍历文件名做 FNV；`sentenceCount` 每次 body 都 split 整段文案。
- **引擎层**（`Shared/Services/AudioPreviewPlayer.swift`，macOS 共用）：
  * `play(url:identifier:startAt:preferAVPlayer:)`：`playbackRate != 1.0 || preferAVPlayer` 时直接走 `playWithAVPlayer`；1x 走 AVAudioPlayer 且 `enableRate = false`（顺序改成先 enableRate 后 rate）。`currentURL` 记录当前 URL 供换引擎续播。
  * `playWithAVPlayer`：`AVPlayerItem.audioTimePitchAlgorithm = .timeDomain`（时域算法，语音变速极低 CPU）；支持 `startAt`（ready 后精确 seek 续播）；结束监听 token 存 `endObserver` 并在 `stop()` 移除（原来泄漏）。
  * ⚠️ **`AVPlayer.play()` 会把 rate 重置成 1**：倍速必须在 `play()` **之后**设，统一收口到 `startAVPlayback(_:)`（play → rate → isPlaying → timer → updateProgress）。`resume()` 的 avPlayer 分支也补 `av.rate = playbackRate`，否则暂停后恢复倍速静默失效。
  * ⚠️ 仍需保留方法末尾一次 `newPlayer.play()` 触发 item 加载，完全不碰 player 时 `AVPlayerItem.status` 可能停在 .unknown、KVO 不触发；紧跟补 `rate`。
  * `setPlaybackRate`：加 `guard playbackRate != rate` 防重复重建音频图；已在 AVPlayer 上只改 `av.rate`；1x 关 DSP；从 AVAudioPlayer 切非 1x 时保存 `currentTime` → `stop()` → `play(url:startAt:preferAVPlayer:true)` 从当前位置续播。
- **UI 层**（`PlayerDetailView.swift`）：`seedHash` 计算属性改成 `seedHashValue()`，Canvas 每帧只算一次，`phase`/`envelope`/`valueNoise`/`hashNoise` 全部改为接收 hash 参数；`sentenceCount` 改 `@State` + `.onAppear` 用 `Self.countSentences(_:)` 算一次。
- 验证：`typecheck.sh` 0 error；`bash tools/ios_build.sh` **BUILD SUCCEEDED**；`ios_build.sh mac` 只报既有 `Launch Screen.storyboard` 错误（Swift 阶段无新错误，共享改动在 macOS 也编译通过）。
