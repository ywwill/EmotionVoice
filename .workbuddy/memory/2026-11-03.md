## iOS 编辑器 accessory 新增「粘贴」按钮
- `EmotionAccessoryBar.swift`：`EditorAccessoryConfig` 加 `onPaste`；控制行在「中断」右侧加 30×30 圆形图标按钮（`doc.on.clipboard`），与「中断」同组（都是往光标处插东西），「清空」仍在 Spacer 右侧。
- `TokenTextEditor.swift`：`AccessoryHost.update` 增加 `onPaste` 参数（回调在 isDark 守卫**之前**赋值），`Coordinator.pasteFromClipboard()` 实现。
- ⚠️ 实现只调 `tv.paste(nil)`，**不自己读 `UIPasteboard.general.string`**：① iOS 16+ 主动读剪贴板会弹「允许粘贴」确认框，系统 paste 通道免弹（连 `hasStrings` 预检都不做，那也是一次访问）② `paste(_:)` 照常触发 `shouldChangeTextIn` → `textViewDidChange` → `TokenDocument.adjust` 自动平移光标后的标记；手写 textStorage 插入要自己补 adjust（粘贴是变长替换，漏了就集体错位）。
- 三语新增 `"粘贴"` 词条（zh-Hans 粘贴 / en Paste / zh-HK 貼上），`plutil -lint` 三份均 OK。`bash tools/ios_typecheck/typecheck.sh` 通过，0 error。
- 已知取舍：走系统 paste 通道会保留源富文本（从本编辑器复制的占位附件粘回来会变成「有 U+FFFC、无对应 mark」的孤儿字符，仅多 14pt 空白、不影响字数）。要强制纯文本可后续加 `UITextPasteDelegate.transformPastedItem`。

## iOS「清空」二次确认
- accessory 的 🗑 不再直接清：`config.onClear` → `Coordinator.requestClear()`，确认后才 `clearAll()`。
- ⚠️ **确认弹窗不能用 SwiftUI `.alert` 挂在 `EmotionAccessoryBar` 上**：accessory 的 `UIHostingController` 在键盘窗口（UITextEffectsWindow）里，从那儿 present 的 alert 会跟着键盘层走（位置飘 / 被盖 / present 警告）。改为 Coordinator 用 `UIAlertController` + `topPresenter()`（取 `textView.window.rootViewController` 往下走 `presentedViewController`，非 keyWindow 时回落到 `UIApplication.shared.connectedScenes` 找 keyWindow）。
- ⚠️ 拿不到 presenter 就 `return`（不做「找不到 VC 就直接清」的兜底），宁可按钮没反应也不能越过确认清正文；顶层已经是 UIAlertController（连点两下）也 `return nil`，不叠弹窗。
- 空输入框不弹（判据 `(tv.text as NSString).length > 0`，标记占占位符所以天然算内容）。
- 新增词条「清空内容」+「文本框里的所有文字和标签都会被清空，且无法恢复。」（en 用 "This cannot be undone."，zh-HK 用 復原、输入框），`plutil -lint` 三份 OK；typecheck 0 error。
