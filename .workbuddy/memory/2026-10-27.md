### 1. 配色：Cold Luxury（琥珀金）→ Aurora Pop
- 需求原文：「优化配色，需要青春靓丽一点」。中性底改雾紫：浅色 grouped `#F5F1FE`、深色 bg `#12101F` / grouped `#0B0916`。

  - `--grad-cta`（按钮，深一档）：浅 `#5B2EDB→#CE2B72`，深 `#7C4DFF→#E23C86`，白字。
  - `--grad-pop`（装饰/发光/网格点亮）：`#8A5BFF → #FF5FA2 → #FFB457`（115°）。
  - 四色分工：紫=主/CTA 起点，玫瑰=进行中/播放头/网格高亮，薄荷 `#2ED9BF`=成功与完成态顶部条，暖橙 `#FFB457`+`#FF9838`=积分计费。

- **情感 30 色不动**（沿用 macOS mapping，浅色向 `#1B1533` 压暗 62%），避免语义色被主色带跑。

### 验证方式（本机 xcodebuild 被沙箱挡住 SPM 解析）
- `xcodebuild` 报 `sandbox-exec: sandbox_apply: Operation not permitted`（SPM Resolve Package Graph 阶段），
  `-disableAutomaticPackageResolution` / `dangerouslyDisableSandbox` 都绕不过。
- 替代：`bash tools/ios_typecheck/typecheck.sh` —— `swiftc -typecheck -disable-sandbox -swift-version 5
  -target arm64-apple-ios18.6-simulator -sdk $(xcrun --sdk iphonesimulator --show-sdk-path) @filelist`，
  61 个文件（iOS 24 + 入口 2 + 复用 34 + Shims 1）；依赖 SPM 的 6 个服务用 `tools/ios_typecheck/Shims.swift`
  的同签名替身顶替。**结果：0 error、iOS 代码 0 warning**；另用 `-default-isolation MainActor` 跑过一遍也 0 error
  （iOSEmora 的 SWIFT_DEFAULT_ACTOR_ISOLATION=MainActor）。
### 真构建已通过（2026-10-27 后续，推翻上面「沙箱绕不过」的结论）
`bash tools/ios_build.sh` → **iOSEmora BUILD SUCCEEDED**（iphonesimulator/arm64），
`bash tools/ios_build.sh mac` → **Emora(macOS) 也 BUILD SUCCEEDED**（证明 4 个共享文件的平台隔离无回归）。
iOS 侧 0 error / 0 warning；剩余 33 条 warning 全在既有 macOS 共享文件（AudioDuration 的 duration deprecated、
AudioPreviewPlayer 的并发捕获 self、BailianTTSService 的 NSLock）。
三个 workaround（**都是受限 shell 的沙箱问题，Xcode GUI 直接 Build 不需要**）：
1. `defaults write com.apple.dt.Xcode IDEPackageSupportDisableManifestSandbox -bool YES` —— 否则 SwiftPM 编译
   Package.swift 时 `sandbox_apply: Operation not permitted`（该开关无 CLI flag，脚本写入、退出时恢复）。
2. `OTHER_SWIFT_FLAGS='$(inherited) -disable-sandbox'` —— 否则宏插件服务 `swift-plugin-server` 报
   "produced malformed response"，第三方包 xctest-dynamic-overlay 的 `@TaskLocal` 宏展开失败。
   ⚠️ **必须 `$(inherited)` 追加**：直接覆盖会丢掉 SPM 包自己的 `-package-name` 等参数，
   supabase-swift 会报 `ambiguous implicit access level for import of 'HTTPTypes'`。
3. `ONLY_ACTIVE_ARCH=YES` —— generic destination 会同时编 arm64 + x86_64 两份，慢一倍且任一架构失败即整体失败。

### 真构建才暴露的两个坑（typecheck 抓不到）
- ⚠️ **PBXBuildFile 的 ID ≠ XCSwiftPackageProductDependency 的 ID**（两者相邻：Supabase 的 buildFile 是 …84、
  product 是 …83）。写错时 Xcode 不会报编译错误，而是在 `ComputePackagePrebuildTargetDependencyGraph` 阶段
  直接崩：`-[PBXBuildFile productName]: unrecognized selector sent to instance`。
  `tools/add_ios_target_files.py` 已改为从 Emora 的 Frameworks 阶段**动态反查 productRef**，不再写死 ID。
- ⚠️ **iOS 侧 `import SwiftUI` 不隐式导出 Combine**：用到 `@Published` / `ObservableObject` 的 iOS 文件
  必须显式 `import Combine`（否则 "does not conform to protocol 'ObservableObject'" +
  "init(wrappedValue:) is not available due to missing import of defining module 'Combine'"）。
  已补：IOSUIState / TabRouter / GenerationDialog / EmotionAccessoryBar。
