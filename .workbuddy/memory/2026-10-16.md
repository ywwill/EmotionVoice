# 2026-10-16

## 采样率默认值改为 22050
- `Models/Constants.swift`：`defaultSampleRate` 由 48000 改为 22050。
- 影响面：`VoiceStudioViewModel.sampleRate` 初值、`AppState.defaultSampleRate` 的 UserDefaults 回退值
  → `VoiceStudioView.onAppear` 用它给 vm 赋值；`SettingsView` 的采样率选择器同样读 appState。
- 注意：AppState 优先读 `UserDefaults["defaultSampleRate"]`（>0 才生效），所以本机若此前选过采样率，
  改常量不会立即生效；清偏好命令：`defaults delete com.emotion.voice defaultSampleRate`
- 候选列表 `Constants.sampleRates` 未动（8000/16000/22050/24000/44100/48000）。

## 积分全链路改为 Double（按实际消耗计费，最多 2 位小数）
- 起因：VoiceStudio 输入几个字符也显示 2 积分——`CreditManager.calculateTTSCredits` 里有
  `max(100, characterCount)` 的 100 字符起扣门槛。用户要求「按实际消耗 + 余额也支持 2 位小数」。
- 去掉起扣门槛：`credits = 字符数 / 100 * rate`，再归一化到 2 位小数（CJK 字算 2 个字符单位，
  见 `TextSplitter.calculateCharCount`）。普通 2 分/百字 → 0.02/字符单位；复刻 5 分/百字 → 0.05。
- 新增 `enum CreditPrecision { static func normalize(_:) }`（CreditManager.swift），
  所有余额加减、消耗计算、云端回落都过一遍 `(v*100).rounded()/100`，避免浮点尾数。
- 类型改动：`CreditManager.balance: Int → Double`、`CreditResult.insufficientCredits(Double, Double)`、
  新增 `deduct(points: Double)`（原来的 `deduct(for:)` 转调它）；`CreditsService.balance/canConsume/
  consume/purchase` 与 `monthlyUsed` 都改 Double；`AppState.creditsBalance/monthlyUsed` 改 Double；
  `CreditServiceError`、`deductForTTS/refundTTS/estimateCredits/currentBalance` 改 Double。
- 云端：`UserCreditsModel.credits`、`SupabaseManager.updateCredits/addCredits/fetchCredits/initializeUser`
  全改 Double。**⚠️ 需要 Supabase 侧把 `user_credits.credits` 列改成 numeric(10,2)**，
  否则小数写入会被 PostgREST 拒（本地照常，下次启动会被云端旧整数值覆盖）。
  SQL：`alter table public.user_credits alter column credits type numeric(10,2) using credits::numeric(10,2);`
- 浮点比较统一带 1e-9 容差（`canConsume` / `hasEnoughCredits` / `checkCredits` / `deduct`），
  避免 0.30 余额扣 0.30 被判成不足。
- VoiceStudioView 生成按钮不再 `Int(points.rounded(.up))`，直接按小数 `canConsume(points)`；
  生成成功后 `deduct(points:)` 用与预估、入库 `pointsCost` 同一个值。
- UI：`CreditsView`/`CreditsPurchaseView`/`StatsView` 余额改走 `formatCredits()`；
  `AudioGenerationModal.remainingCredits` 改 Double，"剩余 %d 积分" 的本地化 key 改成 "剩余 %@ 积分"
  （zh/en 两份 strings 同步改）。
- 校验：swiftc -typecheck（同 10-15 的命令）0 error，warning 均为既有。

## EmotionTokenEditor 改造成「语气胶囊版 v13」（设计稿 UI/emotion_token_editor_capsule.html）
- 视觉换血：语气标签**不再画下划线 + 下方标注**，改成
  「作用域整段文本包进同色胶囊 + emoji/名称徽章压在胶囊左上角」。
  - `EmotionTokenStyle`：删掉 `underlineThickness/underlineGap/underlineJointGap/annotationGap/
    annotationEmojiToLabel/underlineColor/annotationFontSize`，新增 capsule* / badge* 一组参数；
    拟声标记按 v12 瘦身（字号 13→12、内边距 9/3→7/1.5、圆角 8→6、× 直径 16→14、
    fill 0.12→0.10、stroke 0.60→0.45）。
  - `EmotionTokenAttachmentCell`：语气标记变 1×1 **不可见占位**（cellSize 1×1、baseline 0、不绘制），
    不再因为挂标注而撑高行高；只剩拟声标记还在 cell 里画。
  - `EmotionTokenTextView`：新增 `toneCapsuleGeometries()`（胶囊矩形 + 徽章布局，绘制与命中同一份）
    和三段式 `draw(_:)`：**胶囊 → super.draw(文字/拟声) → 徽章**。
- 关键坑（都写进 README 了）：
  1. `tokenView.drawsBackground = false` 必须设——NSTextView 默认刷一层背景，
     在 `super.draw` 里画，会把先铺好的胶囊整片盖掉。
  2. `textContainerInset.height` 18 → 22：徽章向上探出 `badgeTopOffset(12)`，
     首行徽章顶端在 container y ≈ -17.5，22 才不被裁。
  3. `bodyAttributes.lineSpacing` 12 → 22：胶囊实高 28.5（含 2×6 内边距），行距不够相邻胶囊会贴死。
  4. `lm.boundingRect(forGlyphRange:in:)` 高度是**整行**高（含 lineSpacing），
     只有 x/width 可信；胶囊上下沿必须 `baseline ± font.ascender/descender` 推。
  5. 接缝：AppKit 里相邻作用域只隔 1 个字符位（语气标记宽 1px），两侧 8px 内边距必然互压。
     新增 `resolveCapsuleSeams()`：按「lineMinY → minX」排序两两在重叠区中点切开，
     每侧保底 `capsuleSeamMinPadding=2`；拟声 pill 作为 solid 不让位。
     **同一行判据必须用 lineRect.minY，不能用 rect.minY**（胶囊高 28.5 vs pill 高 17，差 7pt）。
  6. 行首/行尾片段要把胶囊夹进容器 [0, width]，否则实测右溢 3pt、左溢 8pt。
  7. 空作用域（标签后没文字）要补一个 `capsuleEmptyWidth` 的兜底胶囊，
     否则徽章无处安放 → 标签变成看不见也删不掉的幽灵。
- 命中：悬停区 = 字形 ∪ × ∪ 徽章 ∪ **整段胶囊**（胶囊让 hover 不丢）；
  小手光标仍**不含**胶囊（正文要保持 I 型可选中），只在 frame/×/徽章/拟声上。
- 验证：写了离屏几何测试（临时编译 EmotionToken 目录 + main.swift 驱动），
  断言胶囊越界 / 徽章被顶部裁 / × 命中 / 悬停命中，全 PASS（接缝重叠 3~4px）。
  为便于测试给 `EmotionTokenTextView` 留了 internal `debugToneCapsuleGeometry()`。
- 校验：swiftc -typecheck 该目录 0 error。

## 胶囊版 v13.1：间距 / 行高 / 顶部裁切四连修（用户反馈）
1. 首行徽章被裁 → `textContainerInset.height` 22 → **28**；`badgeTopOffset` 12 → **14**；
   并给 `toneBadgeLayout` 加 `minY` 参数（= `-textContainerOrigin.y + 2`）兜底压回可见区。
2. 两个语气标签接缝处胶囊重叠 → **语气标记 cell 宽度 1pt → 5pt**（`toneMarkerWidth`）。
   这是两段作用域之间唯一的物理间距，1pt 时两段文本几乎贴死，两侧 8pt 内边距必然重叠，
   再怎么收敛都切不出缝。5pt ≈ 1/3 汉字，是设计稿 CSS `margin: 0 4px` 的 AppKit 等价物。
   配套：`capsuleSeamGap = 2`、`capsuleSeamMinPadding` 2 → **0**，
   `resolveCapsuleSeams` 改成「实心(pill)不让位 → 胶囊单方面让出 gap；两边都是胶囊 → 中点各让一半」。
3. 行高 → `lineSpacing` 22 → **28**（行距 44.5，胶囊间净空 16，徽章顶端离上一行胶囊下沿 2pt）；
   徽章内边距 5/2.5 → **6/3**，文字与 × 间隙 2 → **3**，徽章右移 5 → 6。
4. 胶囊与拟声 pill 重叠 → pill **绘制时左右各内缩 `soundEdgeInset` = 3**（advance 不变），
   名称改为在内缩后的盒子里**居中**排（仍按内边距起排的话右边只剩 1pt）；
   `soundMarkerFrames()` 返回内缩矩形，接缝按看得见的边界算。
- 另一个 bug：空作用域的锚点原本取标记**左边缘**（`loc.x`），会和上一段文本末尾重合 →
  接缝切不出间隙。改成 `loc.x + cellSize().width`（标记的右边缘）。
- 回归（离屏几何测试）：四处接缝间距全部 2.00（胶囊↔pill ×2、胶囊↔胶囊 ×2），
  徽章顶端 view y 8.46，hover/× 命中正常，PASS。typecheck 0 error。

## 胶囊版 v13.2：徽章消失的真凶 —— super.draw 之后的裁剪
- 现象：第一行语气标签的徽章（emoji+文字）完全不显示，胶囊和拟声都正常。
- 排查（离屏渲染成 PNG 直接看 + 临时改红色/换顺序二分）：
  - `drawToneBadges` 被调用、rect 正确、text 非空，但放在 `super.draw(rect)` **之后**画就是不出现在位图里；
  - 同一位置画纯色矩形（在容器内 y=40）能显示，画在容器外（徽章 y≈8.46 < container origin 28）不显示
    → **`super.draw(rect)` 返回后图形状态的裁剪被收窄到文本容器区域**。
  - 胶囊 / v12 下划线都在容器内，所以只有徽章（container y 为负）被裁 —— 极难排查。
- 修复：`draw(_:)` 顺序改为 **胶囊 → 徽章 → super.draw**。
  徽章提前画是安全的：徽章底边（capsuleTop+5）比首行字形顶端（capsuleTop+6.5）高 1.5pt，
  不与任何字形相交；行距 28 下也不压上一行胶囊/拟声；它只盖住自己胶囊的上沿（正是设计意图）。
- 教训：**NSTextView 自绘叠加层一律画在 `super.draw` 之前**，除非确认在容器区域内。
- 验证：离屏渲染 PNG 确认两个徽章（😮 惊叹 / 😢 悲伤）完整显示；typecheck 0 error；几何回归 PASS。
- 排查手段沉淀：`tv.bitmapImageRepForCachingDisplay(in:) + tv.cacheDisplay(in:to:)` 离屏渲染成 PNG
  再用多模态看图，比肉眼在真机上猜快得多（/tmp/tvprobe3 有现成 harness）。
