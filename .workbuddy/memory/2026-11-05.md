用户质疑「声明两个属性有什么意义」。评审结论：**意义不大，已删**，4 处改回 `player.skip(by: ±15/±5)` 字面量，与 macOS `PlayerTransportView` 写法一致。

## VoiceStudioViewModel：#ImplicitStrongCapture（423:59）

`Shared/ViewModels/VoiceStudioViewModel.swift:423:59`：`'weak' ownership of capture 'self' differs from implicitly-captured strong reference in outer scope`。408 行外层 `Task {}` 隐式强捕获 self（443/484/496/… 都在用 self），423 行 `onAudio` 却写 `[weak self]`，所有权表达冲突。

编译器 note（日志 265–266、274 行）给两个静音方式：
- 外层 `Task { [self] in ... }` — `add 'self' as a capture list item to silence`
- 内层写显式赋值 `{ [weak self = self] audioChunk in ... }` — `explicitly assign the capture list item to silence`

验证（**必须做基线对照**）：⚠️ 增量构建不重编该文件时日志里根本没有这条诊断，只 grep 会误判「本来就没警告」。先 `touch` 该文件再 `bash tools/ios_build.sh mac`，基线在 iOS arm64 / x86_64 + macOS arm64 **三个架构各复现一条** 423:59；改后再构建，三架构均真实重编、诊断归零，全文 `warning:` 只剩两条无关的 AppIntents 元数据提示，双 target `BUILD SUCCEEDED`。该文件里用户已有的 `await AudioDuration.read`（481 行）完整保留。

## GenerationDialog:533 —— 默认 MainActor 隔离（本轮所有隔离诊断的总根因）

用户报 `View/iOS/Views/Generation/GenerationDialog.swift:533:36 main actor-isolated static method 'envelope(url:barCount:)' cannot be called from outside of the actor`。基线无需重跑：上一轮 `/tmp/ev_fix_two.log` 304/359 行已复现；`git show HEAD` 确认 HEAD 版就是 `Task.detached { AudioWaveformExtractor.envelope(...) }`。

## 用户纠正：积分数字要 NumberFormatter 本地化（⚠️ 覆盖前面「全局去千分位」的口径）
前面把需求 3 理解成「所有语言都不分组」是错的。经确认的规则（用户选项）：
- **本地化依据 = 系统地区 `Locale.current`**（不是 App 三语切换）；分组符 / 小数点都交给 locale。
- **中文地区不分组**：`zh_*` → `2300` / `12.5`；**其它地区用 locale 默认分组**：en_US `2,300`、de_DE `2.300 / 12,5`、fr_FR `2 300 / 12,5`、ja_JP `2,300`。
- 实测坑：`NumberFormatter` + `Locale(identifier:"zh_CN")` **默认也会输出 `2,300`**，所以「中文 2300」必须显式 `usesGroupingSeparator = false`，不能只靠 locale。
**实现**（`Shared/Helper/Func.swift`）：
- `formatCredits(Double/Int)` 删掉全部 `String(format: "%.0f/%.1f/%.2f")` 手拼，归一化到 2 位后统一 `makeCreditDisplayFormatter().string(from:)`；去尾零交给 `minimumFractionDigits = 0` / `maximumFractionDigits = 2`。
- `makeCreditDisplayFormatter()` 改成 `locale = Locale.current` + `numberStyle = .decimal` + `roundingMode = .halfUp` + `usesGroupingSeparator = !Locale.current.identifier.hasPrefix("zh")`。⚠️ 不覆盖 `groupingSeparator` / `decimalSeparator`（让 locale 自己决定），⚠️ 绝不写死 `en_US_POSIX`。每次返回新实例（NumberFormatter 非线程安全）。
- `AuroraComponents.swift` 的 `AnimatedCreditText` 把 `private let formatter` 改成**计算属性**，否则系统地区在运行时被改动后，缓存的 formatter 会停在旧 locale、与静态文字不一致。
- 全项目积分显示点仍只有 `formatCredits` 一个出口；`Formatters.swift` 的 `separatedThousands` 无调用方、`ProductCardView` 两个 NumberFormatter 是货币价格、CreditsView 的 `Text("\(page)")` 是分页 —— 均非积分，不动。
验证：swift 片段跑 zh_CN/zh_HK/en_US/de_DE/fr_FR/ja_JP × 9 个值，输出与规则逐项一致；`typecheck.sh` 0 error；`ios_build.sh mac` 双 BUILD SUCCEEDED / 0 error。
