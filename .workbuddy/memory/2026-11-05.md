## 复盘：删除 `skipStep` / `longSkipStep` 两个私有常量

用户质疑「声明两个属性有什么意义」。评审结论：**意义不大，已删**，4 处改回 `player.skip(by: ±15/±5)` 字面量，与 macOS `PlayerTransportView` 写法一致。
理由：
1. 每个常量只被引用 2 次，且都是 ± 成对，没有「多处复用」的收益；
2. 数字语义已由 SF Symbol 名 `gobackward.15` / `gobackward.5` 表达，抽常量后变成两处各自维护，改图标忘了改常量就会静默错位；
3. 用户明确要求参考 macOS，而 macOS 就是字面量；
4. 更关键的是「半吊子抽象」：真正重复出现 15 的地方是 `AudioPreviewPlayer+iOS.swift` 的锁屏远程命令（`preferredIntervals=[15]` ×2、`engine.skip(by: ±15)` ×2），View 私有常量管不到，容易误导后来人以为改这里就能全局生效。

什么时候才值得抽：只有把步长上移到 `AudioPreviewPlayer` 层、`View` 与远程命令共用同一个 `static let remoteSkipSeconds` 时才有价值；那种情况下应同时改图标（或由数据驱动生成按钮），否则别抽。

验证：`bash tools/ios_build.sh` → BUILD SUCCEEDED / ✅ 全部构建通过。
