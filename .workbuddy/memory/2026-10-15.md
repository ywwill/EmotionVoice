## Sidebar 选中态改为「滑动高亮」
- 需求：点击切换菜单时，让上一个选中项的背景色「移动」到新的选中项，而非各自淡入淡出。
- 方案：改用 `matchedGeometryEffect` 的共享滑块模式——`Sidebar` 持有 `@Namespace private var ns`，渲染**唯一一个**高亮块 `selectionPill`（`bgElevated` 圆角矩形 + 左侧琥珀指示条作为其 overlay），`.matchedGeometryEffect(id: appState.selectedSection, in: ns)`；放在 `ZStack` 里菜单项之下。
- 每个 `SidebarItem` 新增 `let namespace: Namespace.ID`，并在自身 background 之下再挂一层**隐形锚点** `Color.clear.matchedGeometryEffect(id: section, in: namespace)` 供滑块对齐。滑块 id 与锚点 id 同为 `SidebarSection`（Hashable）。
- `SidebarItem` 的 `itemBackground` 选中态改为返回 `Color.clear`（背景交给滑块），避免与滑块叠加出更深色块；悬浮背景仍保留。
- 关键坑：`.scaleEffect` 必须放在 `.padding`／锚点**之前**（只缩放内容），否则悬浮缩放会连带缩放锚点几何，导致滑块对齐抖动。
- `SidebarItem` 仅在本文件内使用，改签名无外部影响。
- **⚠️ 该方案实测不生效，已被下一节推翻，勿复用「独立 pill + 改变 matched id」的写法。**

## Sidebar 滑动高亮：修正（上一版方案无效）
- 无效原因：上一版是**独立 `selectionPill` + 隐形锚点**，靠**改变 pill 自身的 matched id**（`id: appState.selectedSection`）来移动。`matchedGeometryEffect` 的几何插值依赖「同 id 视图在 A 处消失、在 B 处出现」的配对；pill 是同一个持续存在的视图、只是匹配目标变了，SwiftUI 不做插值 → 无滑动效果。
- 正确写法：每个 `SidebarItem` 在自己的 `.background { }` 里，**仅当 isActive** 渲染高亮块（`RoundedRectangle.bgElevated` + 左侧琥珀指示条作为其 overlay），挂 `.matchedGeometryEffect(id: SidebarHighlight.id, in: namespace)`，**共享固定 id**。切换选中时该 id 在旧项消失、新项出现 → 自动几何插值成滑动。
- `SidebarHighlight.id` 为文件私有常量字符串；悬浮分支用 `else if isHovered` 画弱背景，不参与几何匹配。
- 去掉了原来 item 的 `clipShape`：RoundedRectangle 形状自带圆角，且 clipShape 会把 overlay 里 `offset(x:-15)` 的指示条裁掉。

## 内容区切换让位给 Sidebar 滑动动画（切页卡顿）
- 现象：点侧边栏切到「语音合成」「音色库」时高亮滑动卡顿；切到「积分中心/设置/我的项目」不卡。
- 根因：**不是动画本身**，是**目标页构建/首帧成本与滑动动画抢同一主线程**。`.id(selectedSection)` 使切页整棵子树重建：VoiceStudioView 要建 `EmotionTokenEditor`（NSViewRepresentable → 自定义 NSTextView，附件/tracking area 全量初始化）；VoicesLibraryView 首帧是 20 张 `VoiceCardSkeleton`，每张一个 `repeatForever` 扫光。轻页面无此成本 → 不卡。
- 修复 1（`ContentView.swift`）：新增 `@State renderedSection`（滞后于 `appState.selectedSection`）驱动内容 switch / `.id()`；`onChange` 里 `swapTask?.cancel()` 后延迟 240ms（`Task.sleep(for:)`，常量 `contentSwapDelay`）再无动画事务地赋值。240ms ≈ spring(response 0.36) 的 2/3，位移已完成 ~90%，掉帧落在看不见的尾巴上。连点 A→B→A 时先取消再判等，避免旧调度把内容切回中间态。
- 修复 2（`VoiceCard.swift` 骨架扫光）：去掉 `.blendMode(.screen)`。混合模式让每张骨架单独走离屏合成，20 张同扫时逐帧开销大；暗底上普通 alpha 合成观感几乎一致。
- 经验：macOS 上 SwiftUI 动画卡顿，先怀疑「同帧是否夹带了重建/查询」，而不是调 spring 参数；把重活挪出动画时间窗比改缓动有效得多。

## HistoryView 头部布局钉死（搜索框展开不影响图标/分隔线）
- 现象：搜索框展开后左侧 waveform 图标与下方 Divider 受影响。
- 根因：`[图标][Spacer][搜索框 264]` 的总宽度（图标实际宽度 + spacing 12 + 264）已经顶到栏内可用宽度 300 的上限；`spring` 展开有约 1% 回弹，瞬时宽度再超几 pt → SwiftUI 的 StackLayout **会压缩 stack spacing 来消化溢出**，于是展开/回弹期间图标与搜索框的间距抖动，内容右侧也越界。
- 修复：**两个槽位都钉死，去掉 Spacer**——图标 `.frame(width: headerIconSlot)`，搜索框外面再包一层 `.frame(width: searchExpandedWidth, alignment: .trailing)`，头部整体 `.frame(width: panelWidth - headerPadding*2, height: ...)`。24+12+264 恰好等于 300，展开动画只在固定槽位内部从右往左生长，不参与 HStack 布局计算 → 图标位置、间距、overlay Divider 宽度全程恒定；spring 回弹溢出的几 pt 落在槽位左侧的空白里，碰不到图标。
- 通用经验：**SwiftUI 里给可变宽度控件留"刚好等于可用宽度"的尺寸是危险的**——动画回弹会让瞬时尺寸超出，触发 StackLayout 压缩 spacing 的隐藏行为。要么把控件放进固定宽度槽位（尾部/前部对齐），要么显式留 6~8pt 余量。

## VoicesLibraryView 骨架屏铺到底部、盖住页码切换区
- 现象：`isLoading` 期间骨架网格一路铺到窗口底边，加载完成后真实分页栏才顶出来（布局跳动），骨架也不该占分页栏那条位置。
- 根因两处：
  1. `content` 是三分支 if/else，只有「有数据」分支内部才带 `paginationBar`；骨架分支是一个撑满整个剩余高度的 ScrollView → 占满到底边。
  2. `skeletonGrid` 少了 `singleCategoryCardList` 的 `.padding(.horizontal, 32).padding(.vertical, 20)` → 骨架卡片贴左右边缘、上下无留白，且 `gridWidthTracker` 量到的宽度比真实网格宽 64pt，算出的列数偏大。
- 修复：
  - `content` 改为外层 `VStack(spacing: 0)`：上 `Group{ if isLoading / isEmpty / 真实列表 }`，下 `if isLoading { paginationBarPlaceholder } else if !isEmpty { paginationBar }` → 底部一条始终占位。
  - 新增 `paginationBarPlaceholder`（SkeletonBlock 胶囊 ×3 + 右侧短条，`.frame(height: 27)` 对齐真实按钮高度，同样的 padding 12 / 毛玻璃背景 / 顶部分隔线）。
  - `skeletonGrid` 补上与真实列表一致的 horizontal 32 / vertical 20 padding。
  - `skeletonCount` 由写死的 20 改为按测得列数 × rowsPerPage 动态计算（宽度未知时 5 列兜底），窄窗口下骨架行数与真实页一致，不再多出空行。
  - `VoiceCard.swift` 里 `private struct SkeletonBlock` 去掉 private（分页栏骨架要复用）。
- 经验：**骨架屏必须复刻真实布局的「外框结构」而不只是卡片形状**——固定的底部工具条要在骨架阶段也占位，否则加载完成瞬间会顶出来抖动。

### 骨架屏后续修正（用户追加要求）
- 要求：骨架固定「5 列 × 4 行 = 20 张」，且**骨架卡片必须与真实卡片尺寸一致**。
- 回退上一轮的动态 `skeletonCount`（按测得列数算）：改为常量 `skeletonColumns 5 × rowsPerPage 4`，`ForEach(0..<(Self.skeletonColumns * Self.rowsPerPage))`。
- 尺寸一致的做法（关键）：**不再手写 SkeletonBlock 拼骨架**，改为
  `VoiceCard(item: 占位 item, isSelected:false, isPlaying:false, on*:{})` + `.redacted(reason: .placeholder)` + `.allowsHitTesting(false)` + 原扫光 overlay。
  - 原理：redacted 只替换渲染、frame 不变（占位块尺寸 = 原文本尺寸），由 SwiftUI 保证骨架与真实卡片逐像素同高；省掉手算字号行高。
  - `isPlaying:false` 必须传，否则波形（RoundedRectangle 不会被 redact）会露出彩色条。
  - overlay 要加在 `.redacted()` **之后**，否则扫光会被一起灰化。
- 占位数据 `placeholderItem` 按真实 catalog 最常见形态取值：name 4 字、desc 4 字（**单行**；真实 feature 文案都是 4~6 字，写两行会让骨架偏高）、age + gender 都有（保留 metaTags 行）、tier .premium。
- 经验：**要骨架和真实控件同尺寸，优先复用真实视图 + redacted，而不是手写一套占位块**——手写必然要猜字号/行高/默认 spacing，改版型时还会失同步。

## VoiceLibrarySheet 右上角两个 × 并排（工具栏 UI 冲突）
- 现象：sheet 入口的 `VoicesLibraryView` 右上角有「关闭 sheet」的圆形 ×；点搜索展开后，搜索框内又出现「清空并收起」的细 ×，两个叉并排，语义互相干扰。
- 方案：搜索展开时让**关闭 sheet 按钮让位**（不是删搜索框内的清除按钮——清空搜索是更常用的动作，且左侧菜单入口下它是唯一清除入口）。
  - `ExpandableSearchField` 新增可选回调 `onExpandedChange: ((Bool) -> Void)?`（默认 nil，HistoryView 不受影响）；body 里 `.onChange(of: isExpanded)` 转发，并补 `.onAppear { onExpandedChange?(isExpanded) }`（初始因已有搜索词而展开时 onChange 不触发，宿主会漏同步）。
  - `VoicesLibraryView` 新增 `@State isSearchExpanded`；关闭按钮条件渲染 `if let w = sheetDismiss, !isSearchExpanded`，加 `.transition(.opacity)`，HStack 上挂 `.animation(.easeOut(0.2), value: isSearchExpanded)`。
  - 布局不跳动的关键：`searchExpandedWidth = sheetDismiss == nil ? 220 : 220 + closeButtonSlot(42)`（按钮 30 + 间距 12）。让位后这 42pt 由搜索框吃掉，展开态右边缘仍贴 32pt 边距，且这是**构造期常量**，不依赖 isSearchExpanded 回调时序，避免展开动画中途跳宽。
- 关闭 sheet 的替代路径：Esc（SwiftUI sheet 默认）/ 收起搜索后按钮回归。
- 经验：**同一行出现两个同形图标时，优先让"次要/临时状态触发的那个"让位，并把腾出的宽度让给相邻控件**，而不是留空白或加间距；宽度补偿要用构造期可确定的常量，不要用状态回调驱动（会慢一帧导致动画抖）。

### 工具栏按钮冲突 —— 最终方案（推翻上一轮的"让位"方案）
- 上一轮做法（搜索展开时隐藏关闭按钮）**被用户否决**：搜索期间无法关闭 sheet，功能缺失。
- 教训：**不要用"隐藏控件"来解决视觉重复**，那必然牺牲功能；应该改**形态**让两者可区分。
- 最终方案（用户在四选项中选定）：右上角圆形 × 改为**纯文字胶囊按钮「关闭」**（12pt medium + `AppColor.textSecondary`，padding h12/v6，bgTertiary + borderSubtle 描边，`StaticButtonStyle`），关闭按钮**常驻**；搜索框内保留小 × 作为「清空并收起」。两个控件形态完全不同，功能都不丢。
- 已回滚的临时改动：`ExpandableSearchField` 的 `onExpandedChange`（整段删掉，不留未使用 API）、`VoicesLibraryView` 的 `isSearchExpanded` / `closeButtonSlot` / `searchExpandedWidth`。
- 本地化：新增 `"关闭"` key，`zh-Hans.lproj` 与 `en.lproj` 各加一条（en = "Close"）。
