## VoicesLibraryView 首屏骨架屏优化
- 根因：`VoicesLibraryViewModel.init` 同步调 `reloadCurrentPage()`（全表过滤排序 + 逐分类 ~17 次 `count` + 取当前页 20 Voice），且 `.onAppear` 的 `syncFromAppState`/`jumpToVoice` 又各调一次 —— 首屏同步加载两遍，全堵主线程导致出现卡顿。
- 修复：VM 新增 `@Published isLoading`（默认 true）；`init`/`syncFromAppState`/`jumpToVoice` 不再同步加载；新增 `load()` 统一取数后 `isLoading=false`。视图在 `.onAppear` 用 `Task { vm.load() }` 异步触发，先让骨架屏上屏再加载；`onDisappear` 取消任务。`setPageSize`/`commitPageSize` 在 `isLoading` 期间只定列数不取数，避免骨架期被提前/重复触发。
- 新增 `VoiceCardSkeleton` + `SkeletonBlock`（带横扫光动画）与 `gridWidthTracker`（骨架/真实网格共用宽度测量），`content` 按 `vm.isLoading` 分支：骨架（4×5=20 占位）→ 空态 → 真实网格。

## 骨架屏不显示的修复（VoicesLibraryView）
- 现象：菜单入口进入 VoicesLibraryView 看不到骨架屏，直接出真实网格。
- 根因：`.onAppear` 里 `Task { @MainActor in vm.load() }` 虽异步调度，但 `load()` 前无真正挂起点，重查询在**同一 runloop 迭代**内同步跑完把 `isLoading` 置回 false；Core Animation 每轮只提交一次最终状态，骨架在绘制上屏前就被真实网格覆盖。
- 修复：在 `vm.load()` 前加 `await Task.yield()`，让出主线程先把骨架这一帧提交到屏幕，再执行重量级查询。改动仅 `VoicesLibraryView.swift` 的 onAppear 任务体，未引入并发（VoiceService 共用单 SQLite 连接，不可后台查询）。

## 音色名本地化修复（voice name localization）
- 根因：`VoiceService.displayName(forKey:)` 原返回写死的 `voice.name`（中文名），不跟随系统语言。
- 修复 1（PlayerMetaStrip 播放条 `音色` 列 + AudioRowItem 历史列表头像）：`displayName` 改为返回 `voice.localizedName`（`Voice` 已有按 `AppLanguage.isChinese` 选 `name`/`nameEn` 的属性）。调用方无需改，缓存仍按 key 存、语言启动时定。
- 修复 2（CreditsView 积分记录「详情」列）：消耗记录的 `title` 是入 SQLite 时存的中文 `consume.voiceName`，英文模式会显示中文。改为在 `fetchCreditRecords` 用 `VoiceService.shared.displayName(forKey: consume.voiceKey) ?? consume.voiceName` 重新解析当前语言名，存的中文名兜底；购买记录 `title` 已是 `"购买积分".localized()` 不受影响。
- 结论：音色名属 `VoiceCatalog.strings`，不能在调用处套 `Localizable` 的 `.localized()`，必须由 `VoiceService` 按 `voiceKey` 解析。
