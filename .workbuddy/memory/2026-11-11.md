## 语音指令自动拼接本地化（iOS + macOS 共用 VM）
- 现象：英文界面点语言 chip（如 Chongqing Dialect），指令框自动填入的是简体中文「重庆话,温柔的女性声音，…」。
- 根因：`VoiceStudioViewModel.updateNLInstruction()` 直接拼 `selectedLanguage`（中文 key）与 `Constants.instructionForPreset()`（中文 instruction），**从未调 `.localized()`**；三份 strings 里 24 个语言名 + 6 条预设描述的译文早就齐备，只是没被用上。
- 修复（只改 VM 一处，两端共用）：两处都走 `.localized()`；分隔符中文沿用半角 `,`（零回归）、英文用 `, `（`AppLanguage.isChinese` 判定）。
- macOS 排查结论：`VoiceStudioView` 用同一个 `VoiceStudioViewModel.toggleLanguage/applyPreset`，`nlInstruction` 就是 VM 属性，视图只有 TextEditor Binding，没有独立拼接逻辑 → 自动一并修复，无需改 macOS 代码。
- 验证：`typecheck.sh` 通过（仅两条既有 warning）；静态校验三份 strings 的 24+6 = 30 个 key 全覆盖、无重复、译文无 `%`（`.localized()` 内部 `String(format:)` 无参调用安全）；三语输出推演：en `Chongqing Dialect, A gentle female voice with a moderate speaking pace...` / zh-HK「重慶話,溫柔的女性聲音…」/ zh-Hans 保持原文。

## 语音指令语言 → 百炼 language_hints
- 需求：`StudioParamSheet`(iOS) / `nlLanguageSelector`(macOS) 选中 16 种官方语言时，生成请求带 `language_hints`；默认为空。
- 文档口径（Qwen-Audio-TTS 客户端事件）：在 `run-task` 的 `payload.parameters`，类型 `array[string]`，**当前版本只处理第一个元素**，建议只传一个值；合法值 zh/en/fr/de/ja/ko/ru/pt/th/id/vi/es/it/ms/fil/ar；`other` 只适用 `qwen-audio-3.1-tts-flash`，本项目不用（线上模型是 `qwen-audio-3.0-tts-plus`）。
- 实现链路（iOS/macOS 共用 VM，正式生成才带、音色试听不带）：
  - `Constants.swift`：`NLLanguageItem` 加 `languageHint: String?`（自定义 init 默认 nil），前 16 项填值、8 个中文方言留空；新增 `Constants.languageHint(forName:)`（按 `selectedLanguage` 中文 key 查）。⚠️ 方言按用户要求**不下发**，别顺手映射到 `zh`。
  - `VoiceStudioViewModel.generate()` → `synthesizeWithTimeline(languageHint: Constants.languageHint(forName: selectedLanguage))`。
  - `BailianTTSService`：`synthesizeWithTimeline → runSynthesize → performSynthesize → buildSynthesizeRequest` 逐层透传；`buildSynthesizeRequest` 写 `payload["language_hints"] = [hint]`，无值**不写字段**（默认空，比传 `[]` 安全）；`synthesizeAsync` 试听传 nil；字级时间戳降级重跑保留 hint。
  - `supabase/functions/bailian-tts/index.ts`：`TTSRequest.language_hints?: string[]` + `ALLOWED_LANGUAGE_HINTS` 白名单兜底 + `buildRunTaskEvent` 只取第一个合法值写进 parameters + `logRequest` 打印该字段。
- ⚠️ 已部署并核对：`supabase functions deploy bailian-tts --project-ref dpyyhbqqmegencxekkcr` → `functions list` 由 **v13 → v14**（2026-11-11 03:10:35 UTC）。只改本地不部署会被线上旧版静默丢弃（同 word_timestamp_enabled 的坑）。
- 验证：`typecheck.sh` 通过（两条既有 warning）、`deno check index.ts` 通过、脚本比对 Swift 16 hints 与 TS 白名单完全一致、方言 8 项不下发、调用链 grep 无遗漏。老客户端不传字段 → 行为不变。
