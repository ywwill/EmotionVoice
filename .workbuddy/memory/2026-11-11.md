- 需求：`StudioParamSheet`(iOS) / `nlLanguageSelector`(macOS) 选中 16 种官方语言时，生成请求带 `language_hints`；默认为空。

  - `BailianTTSService`：`synthesizeWithTimeline → runSynthesize → performSynthesize → buildSynthesizeRequest` 逐层透传；`buildSynthesizeRequest` 写 `payload["language_hints"] = [hint]`，无值**不写字段**（默认空，比传 `[]` 安全）；`synthesizeAsync` 试听传 nil；字级时间戳降级重跑保留 hint。

## 拟声标签漏显 + 逐字高亮与声音错位（19:09 反馈）
- 现象：阅读区仍能看到 `[deep and loud shouting][giggles]` / `[clears throat]`；同时 5 句的时间码 0/11.9/18.0/37.0/44.4 明显超出音频总长 00:29，高亮与声音对不上。
- 标签根因：**上游把含空格的标签劈成两个 word**（`[clears` + `throat]但真正…`）。我上一版是逐词扫，`[` 与 `]` 分属两词 → 两边都不成对 → 标签原样漏出。`[curious]` / `[very fast]` 是单词所以正常，只有「含空格的标签」翻车（这就是为什么一半生效一半不生效）。
  - 修法：`TranscriptTagMarkup.line(for:)` 改成**把整句拼成字符流再扫**（同时记 `owner[]` 每个字符属于第几个词），摘完按归属把字还回去 → `words` 仍与 `cue.words` 同长度，逐字高亮下标零改动。`officialTag` 匹配改成**忽略所有空白 + 忽略大小写 + 兼容全角方括号**（跨词拼回来可能没有空格）。touched 词只剩空白时清空；正文首词去前导空白。`/tmp/tagcheck3.swift` 12 组样本全过（含跨词、整词、全角、大小写、`[注]` 保留、英文词间空格）。
- 时间错位根因：`AudioConcatenator.durationSeconds` 对 mp3 写死 **32 kbps** 按字节估时长。上游实际码率更高 → 每段时长成倍偏大 → 段偏移累积把后几句推过音频末尾（实测首段 11.9s 对不上 26 个字的真实时长，≈2 倍）。真实 mp3 验证：字节估算 2114s vs 真实 211s（10 倍），必须按帧算。
  - 修法：新增 `AudioConcatenator.mp3DurationSeconds`，走 MPEG 帧头逐帧累加（跳 ID3v2、只认 Layer III、1152/576 samples、码率表 v1/v2）。用两个真实 mp3 与 `afinfo` 对齐到 ±0.03s。
  - VM 侧收尾：`assemble(applyOffsets:)` 生成「加偏移 / 不加偏移」两版，若加偏移后末字超出音频时长 >500ms 则改用不偏移版本（上游可能本来就给绝对时间）；并打诊断日志「段 N 估算时长 / 上游末字 / 合计 vs 实际」。
  - `AudioItem.timeline` 加**兜底校验**：末字 > 音频时长 ×1.2 判为不可用 → 退回静态原文（旧 sidecar 的偏移是错的、又无法在不重合成的前提下修正，宁可没有高亮也不显示错位高亮）。
- ⚠️ 旧音频不会自动修好：sidecar 里的段偏移已经烧进数值，只能重新生成一条音频拿到正确时间轴。
