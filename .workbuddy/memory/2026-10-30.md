# 2026-10-30

## iOS TokenTextEditor：输入卡顿 + 标签不显示（4 个问题一起修）

改动文件：`iOSEmora/Views/Studio/{TokenTextEditor,TokenCapsuleOverlay,TokenDocument}.swift` + `StudioView.swift`。

### 根因
1. **打字卡顿**：每敲一个字 → 写两个 `@Binding`（doc/marks）→ 整个 StudioView body 重算 →
   `updateUIView` → `AccessoryHost.update()` 无条件 `hosting.rootView = AnyView(bar)`，
   把键盘上方那 23+7 个胶囊按钮的 SwiftUI 树整棵拆掉重建并重新布局。accessory 在输入关键路径上，
   一个键击来一次就是肉眼可见的卡。
2. **语气标签点了不显示**：`draw()` 里 `guard length > 0 else { continue }` —— 空作用域（在文末 / 空文档
   点标签）画不出 0 宽胶囊，徽章也无处安放 → 变成「看不见也删不掉的幽灵」。macOS 侧有兜底胶囊，iOS 漏了。
3. **拟声标签点了不显示**：① 同 1 的 overlay 尺寸问题（见下）；② 插入/删除占位符是直接改 `textStorage`，
   不走 `shouldChangeTextIn`，所以 `TokenDocument.adjust()` 没被调用 —— 光标之后的标记整体错位 1 格。
4. **界面切换卡顿**：切标签会重算 StudioView body → 又一次 `updateUIView` → 同一套 accessory 重建。

### 修法
- 新增 `TokenEditorStore`（`@MainActor ObservableObject`）：`doc`/`marks` **故意不做 @Published**，
  只有 `charCount`（0.25s 合并）+ `contentRevision`（外部整体改写时自增）发布。
  → **打字完全不经过 SwiftUI**，全部在 UIKit 内闭环。
- `TokenTextEditor` 签名从 `@Binding doc/marks` 改为 `let store: TokenEditorStore`。
- `AccessoryHost.update(palette:isDark:...)`：`hosting.rootView` 只在深浅色翻转时重建。
- `updateUIView` 里 overlay 的外观字段全部加相等判断，只有真变了才 `setNeedsDisplay()`。
- `TokenCapsuleOverlay`：**`autoresizingMask = [.flexibleWidth, .flexibleHeight]`**。
  ⚠️ 这是「标签完全不显示」的真正元凶：overlay 是 UIScrollView 子视图，`makeUIView` 时 tv.bounds 是
  `.zero` → overlay frame 恒为 0 → 自身 `layoutSubviews` 永远不被触发 → 自己算 frame 的逻辑跑不到、画布 0 尺寸。
- 新增 `emptyScopeRect(characterIndex:)`：空作用域取**前一个字符的右边缘**做锚点，配 `emptyScopeWidth = 34`
  兜底胶囊（沿用 macOS「空作用域锚点取标记右边缘」的规则）。
- `TokenDocument.scopeEnd`：原来取「数组顺序里第一个」，改成取**位置最近的**（min），否则相邻两段胶囊重叠。
- `insert` / `removeMark` 手动调 `TokenDocument.adjust()` 补 ±1 位移。
- `hitTest` 去掉多余的 `convert(point, from: tv)`（point 本来就在自己 bounds 里）。

### 验证
- `bash tools/ios_typecheck/typecheck.sh` → iOS 侧 0 error / 0 warning。
  ⚠️ 该脚本原指向已废弃的仓库根 `iOS/`，已改为 `EmotionVoice/iOSEmora`。
- ⚠️ `bash tools/ios_build.sh` 当前跑不通：**本地 SPM 缓存损坏**（6 个包 git object 读不出来，
  `Could not resolve package dependencies`），与代码改动无关，在编译前就失败。
  修复：Xcode → File ▸ Packages ▸ Reset Package Caches（或删 `~/Library/Caches/org.swift.swiftpm`
  + DerivedData/SourcePackages）。
  试过 `git -C <缓存仓库> fetch --all` 补救，只对部分仓库生效（沙箱内走代理常 502），不可靠。

## 第二轮（用户反馈：标签输入后消失 / 拟声 pill 高度错 / 切页仍卡）

- **`TokenDocument.adjust` 对零宽标记的规则是反的**（「选完语气标签一输入，标签就没了」的真因）：
  旧规则 `mark.location >= editedRange.upperBound → +delta`，在插入点打字时 `L >= L` 成立，
  标记被推到光标后面一格；每敲一字后移一格 → 作用域恒为空 → 看不见。
  新规则：**语气/中断零宽标记 `mark.location <= editedRange.location` 就原地不动**（新输入归它管）；
  落在替换区间内部则**夹回区间起点**而不是删除（拼音整段替换命中时不能静默吞标签）。
  拟声占 1 个真实字符（U+FFFC），仍走「随字符消失」的旧规则。
- **拟声 pill**：不再铺 `pillFillAlpha` 底色（会在标签文字后面压出一块「背景图」）；
  高度固定 `pillHeight = 20` 并垂直居中 —— ⚠️ 不能拿 `lineRects` 的行高当高度，
  正文 `lineSpacing = 26` 会把行片段撑到 45pt，画出来是和整行一样高的色块。
  绘制改用附件自身矩形（`lm.boundingRect(forGlyphRange:)`），不用归一化后的整行矩形。
- **真正的全局卡顿源（与编辑器无关）**：`VoiceStudioViewModel.voice` 是 `fetchAll().first(where:)`，
  而它是 SwiftUI body 里的计算属性，`voiceRow` + `voiceSubtitle` 一次 body 求值就调用 **5 次**
  → 每次 body 求值 5 次全表扫描 + 全量排序。切标签 / 打字 / 任何 @Published 写入都会中招。
  修法：`VoiceService` 新增 `voice(forKey:)`（`NSCache<NSString, VoiceBox>`）+ `invalidateVoiceCache()`；
  失效点 = `toggleFavorite` 与 `DatabaseManager.rebuildVoices`（后者 post `Notification.Name.voicesDidReload`，
  `VoiceService.init` 里监听）。
- A/B 开关 `IOSPerfDebug.usePlainTextEditor`（StudioView.swift）：置 true 用系统 `TextEditor` 顶替自绘编辑器
  （不加载胶囊层、不挂 accessory），10 秒判定卡顿是否与 `TokenTextEditor` 有关。
- ⚠️ `tools/ios_typecheck/Shims.swift` 里有一套**替身类型**（`VoiceService`/`DatabaseManager` 等），
  真实文件改动若加了新方法，必须在 Shims 里同步加桩，否则 typecheck 报 "has no member"。
  反过来说：Shims 覆盖的文件（VoiceService / DatabaseManager）**不参与 typecheck 编译**，
  改它们要另外用 `swiftc -parse` 兜一遍语法。

## 第三轮：创作页布局 + 胶囊接缝（对齐 macOS EmotionTokenEditor）

### 1. 输入框撑满底部
- 窄屏**去掉 ScrollView**：`VStack { paramsStrip; textCard }` + `generateBar`，`textCard` 用
  `.frame(maxHeight: .infinity)` 独占剩余高度，`padding(.bottom: 10)` → 与 generateBar 隔 10pt。
- ⚠️ 编辑器高度必须靠 **GeometryReader** 给（`geo.size.height` 直接喂 `.frame`）。
  不能只写 `.frame(maxHeight: .infinity)`：`UIViewRepresentable` 没有有意义的
  `intrinsicContentSize`，SwiftUI 会把 UITextView 压成 0 高。
- 宽屏仍在 ScrollView 里（高度无界），所以 `textCard.frame(minHeight: metrics.editorMinHeight)` 兜底，
  否则 maxHeight:.infinity 会塌成 0。
- `TokenTextEditor` 的 `minHeight` 参数一直是死参数，已删。

### 2/3. 多个语气标签重叠 + 拟声处胶囊不中断
两件事都源于「iOS 少了 macOS 的 `resolveCapsuleSeams`」，已完整移植：
- `TokenDocument.orderedMarks(_:)`：**位置序**（同位置按插入序，不能用 `sorted{location<}`，
  Swift 的 sorted 不稳定）—— 同位置插两个语气标签时，顺序错了两段作用域会都撑到文末、完全重叠。
- `TokenDocument.scopeEnd(at:in:docLength:)`：改用**位置序里的下一个**边界，不再用
  `other.location > mark.location`（后者漏掉同位置的标记 → 全重叠）。
- `TokenDocument.scopePieces(start:end:soundLocations:)`：作用域按拟声占位符切段，
  胶囊在 pill 处**断开**（pill 不再垫在同色底上）。
- `TokenCapsuleOverlay.resolveSeams(_:gap:minPad:)`：按「行 → x」排序两两收敛，
  `capsuleSeamGap = 2` / `capsuleSeamMinPadding = 3`；**拟声 pill 是 isSolid 不让位**，
  间隙由胶囊单方面让出。胶囊左右各 `capsulePadX = 8`，相邻两段原本重叠 16pt。
- 新增 `pillRect(charRange:...)`（量 pill，供接缝用）+ `clampX(minX:maxX:)`
  （行首/行尾夹进容器，否则胶囊伸出被裁）。
- `drawCapsule` / `drawPill` 入参改为**收敛后的最终矩形**，不再自己加 inset / 自己算行高。
- ⚠️ 木有真机构建环境：SPM 缓存损坏 + 外网被代理拦（502），只能靠 typecheck 验证。

## 第六轮：修「换行后胶囊互相重叠」（TokenCapsuleOverlay 几何根因）

现象：文本一换行，上下两行的语气胶囊就叠在一起、徽章压字、拟声 pill 掉到行间空档。

根因：**TextKit 把 `NSParagraphStyle.lineSpacing` 算进了 `lineFragmentUsedRect`** ——
16pt 正文 + `lineSpacing = 26` → usedRect 高 **45pt**，而字形只贴在它顶部那 19pt。
`lineRects` 直接 `r.size.height = usedRect.height` → 胶囊高 45+6×2 = **57pt > 行距 45pt**，
于是相邻两行必然重叠 11pt（截图实测：胶囊顶边 640 / 底边 817，下一块顶边 781，重叠 34px）。
`boundingRect(forGlyphRange:)` 的 y/height **同样含行距**，所以 `pillRect` 取 `raw.midY`
会把 pill 往下推 13pt，正好落进行间空档。

验证手段：写了 `/tmp/lmprobe.swift`（AppKit 的 NSLayoutManager 当等价探针，swiftc + AppKit 可直接跑）：
行高 18（UIKit 19）→ usedRect 44（=18+26）、`location(forGlyphAt:).y = 15` ≈ ascender
（说明字形贴在 usedRect 顶部）、最后一行 usedRect 18（无行距）。

修法：
- 新增 `Config.lineSpacing`（默认 26），`TokenTextEditor.makeUIView` 里 `overlay.config.lineSpacing = Self.lineSpacing` 同步。
- 新增 `textLineBox(glyphIndex:...)`：行高 = `max(usedRect.height − lineSpacing, fallbackLineHeight)`，
  再用 `min(_, max(usedRect.height, fallbackLineHeight))` 兜住；段落末行没行距也安全。
- `lineRects` / `emptyScopeRect` / `pillRect` 三个函数统一走 `textLineBox`；
  pill 改成以字高块 `box.midY` 居中（不再用 `boundingRect.midY`）。
- 收敛后：胶囊 19+12 = 31pt、行距 45pt → 行间留 14pt；徽章（15pt，压胶囊上沿 13pt）
  离上一块胶囊底边还有 1pt —— `lineSpacing = 26` 本来就是为徽章留的。

验证：`typecheck.sh` 0 error。`ios_build.sh` 仍是 SPM 缓存损坏（`unable to read tree`），非代码问题。
