## AudioGenerationModal 四个问题修复
1. 去掉完成态 ScrollView + MeasuredHeight 偏好测量（弹窗改为内容自然高度）。
   ⚠️ 该 ScrollView 有隐患：measured height → 改 ScrollView 高度 → 再测 → 可能来回震荡，
   播放时 10Hz 重绘会放大成主线程死循环（卡顿 / CPU 100% 的元凶之一）。
2. **坑：`let ticker = Timer.publish(...).autoconnect()` 在弹窗里永远不会触发**。
   接收中 `vm.receivedBytes` 每块一变 → 弹窗反复重建 → Combine 订阅被取消重连 →
   计时器走不满一个周期。改用对象持有真实 Timer（`StatsTicker: ObservableObject`
   + `RunLoop.main.add`），配 `.onReceive(ticker.$now)`。首次取样直接用瞬时值，之后指数平滑。
3. 播放卡顿：波形进度条从「60×2 个 SwiftUI 形状 + 每条一个渐变」改成单个 `Canvas`
   （底层灰条一遍、已播放层 clip 后一遍），每帧一次绘制；
   另在 `AudioPreviewPlayer.updateProgress()` 里加变化阈值，只在值真变了才写 @Published
   （`duration` 原来每 0.1s 无脑重赋，白触发所有订阅视图重绘）。
4. 数据块日志是真实数据：`vm.receivedBytes` ← `BailianTTSService` 每次
   `onAudio(binaryData)` 的 `audioChunk.count` 累加；仅做 200ms 内多块合并成一行（防刷屏），
   段号 `chunkCount` 仍是真实段数。
- 后续（频谱只占一半 + 卡顿）：
  - `StreamingWaveView` 重写：条数按容器宽度自适应（6px 条 + 6px 间距，约 43 根）铺满整条，
    并去掉 TimelineView 30fps 重算，改为每根条挂 `repeatForever` 缩放动画
    （duration 0.9+i%5*0.11、delay i*0.055，等价 CSS），动画跑在渲染服务端。
  - **卡顿根因**：WebSocket `onAudio` 每秒几十上百次直接写 `@Published receivedBytes /
    generationProgress` → 整个 VoiceStudioView（内含 NSTextView 编辑器）跟着重绘。
    VM 新增 `receivedChunks`(@Published) + pending 缓冲（`pendingBytes/pendingChunks/
    pendingProgress`），约 10Hz 统一 `flushReceiveStats()`，流结束后再补刷一次保证总数准确。
    段号改读 `vm.receivedChunks`（真实段数，不受节流与日志合并影响）。
- `BailianTTSService` 打开每帧二进制日志：`[WS RECV] #n 本次 x B · 累计 y B`。
- **弹窗期间鼠标/焦点被 EmotionTokenEditor 抢走**：
  - `EmotionTokenEditor` 新增 `isInteractive: Bool = true`，VoiceStudioView 传
    `isInteractive: !showGenerationModal`。updateNSView 据此设
    `tokenView.isEditable/isSelectable` 并 `invalidateCursorRects(for:)`；
    不可交互时若焦点在文本域则 `makeFirstResponder(nil)`，恢复可编辑时再把焦点还回。
    makeNSView 里 `isInteractive == false` 不再抢焦点。

    比只靠窗口级 `disableCursorRects()` 更可靠。）

  - 新增 `ModalAudioPlayer`（弹窗内播放器子视图）与 `ModalWaveCanvas`：
    只有 `ModalAudioPlayer` 用 `@ObservedObject` 订阅 `AudioPreviewPlayer`；
    弹窗本体改用 `let` 传 audioURL + duration，播放期间不再被进度刷新带着重算。
    删掉弹窗自有的 0.1s `playbackTimer` / `playbackProgress` / `isPlaying`

  - `ModalWaveCanvas` 对齐 `PlayerWaveformView`：所有柱子合成 2 条 Path，各 fill 一次

## 快捷键方向键（前进/后退）无效的修复
- 现象：播放面板里按 ←→ / ⇧←→ 快进退没反应（空格可能也受影响，但用户在列表/空白焦点下测空格正常）。
- **根因在 `PlaybackKeyboardShortcuts.swift` 的 `shouldIntercept()`**：旧判断用
  `responder is NSTextView || responder is NSTextField || 类名含 "Text"/"Search"` 来决定
  "焦点在输入框就放行"。但 SwiftUI 的只读 `Text`（如右侧原文卡片/元信息）在 macOS 上被点中进入
  **选择态**会变成一个内部的 `NSTextView`，于是被误判为"输入框"而放行方向键 ——
  方向键被用来移动文本光标而非快进，表现就是"无效"。
  （空格同理会被吞进只读文本视图，只是空格在只读文本里无副作用，不易察觉。）
- **修复**：`shouldIntercept()` 改为只放行**真正在编辑**的可编辑文本
  （`NSTextView.isEditable == true` 或 `NSTextField`，如搜索框），其余（只读文本选择态、
  列表 NSTableView、空白）一律接管为播放快捷键。
- **顺带修了一个隐藏雷**：`action(for:)` 里把 `modifierFlags` 跟 `[.shift]` 比较时，
  直接 `.intersection(.deviceIndependentFlagsMask)`，而该 mask 含 `capsLock` ——
  **只要开了大写锁定，所有快捷键（含空格）全会失效**。现改为先 `.subtracting(.capsLock)`。
- **新增规则**：没有正在播放的内容（`player.playingKey == nil`，即未播放或已播完）时，
  ←→ / Home / End 不再被吞成无操作，而是 `return event` 交还给左侧列表做行导航；
  只有空格始终用于 播放/暂停。播放中则 ←→ 快进、↑↓（我们直接放行）仍由列表做行选择。
- 类型检查：本文件零报错；`AudioGenerationModal.swift` 当前有一堆 error 是用户本地
  VoiceStudio 开发改动（重复声明 `fileSizeText`、移除 `playbackTimer` 等，git 状态 MM）引入的，
  与本次快捷键修复无关。

## AudioGenerationModal 接收数据单位自适应 B/KB/MB/GB
- 需求：接收中的「已接收」大数字原来**只显示 KB**（`formatKB`，如 `2,180,000.00 KB`），
  数据一大就变成天文数字。要求自动在 B / KB / MB / GB 间切换。
- 改动 `AudioGenerationModal.swift`：
  - 删 `kbNumberFormatter` + `formatKB(_:)`，换成
    `receivedNumberFormatter`（千分位两位小数）+ `autoByteUnit(_:) -> (value, unit)`
    （按 1000 进制自适应：<1000→B，<1e6→KB，<1e9→MB，否则 GB；B 走整数，其余两位小数）。
  - 接收中「已接收」：`Text(rx.value)` + `Text("%@ 已接收".localized(rx.unit))`，
    速率 `Text("↑ \(sp.value) \(sp.unit)/s")` 也跟着自适应（不再写死 KB/s）。
  - `formatDataSize` 兜底补 GB（完成态「大小」格用），防止超大文件只显示 MB。
  - 本地化：zh/en 的 `Localizable.strings` 把旧键 `"KB 已接收"` 改成占位符 `"%@ 已接收"`
    （中文 `%@ 已接收` / 英文 `%@ received`），"单位"用参数传入，符合"动态拼接用占位符"约定。
  - 同步更新设计稿 `UI/audio-streaming-modal.html`：新增 JS `fmtBytes()`，
    接收中 headline / 顶部后台提示条 / rate 都改用自适应单位，保持与 Swift 一致。
