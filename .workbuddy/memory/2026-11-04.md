## 回退 iOS 专用播放器 + 定位播放 CPU 暴涨根因
- 用户反馈：「还是使用 `AudioPreviewPlayer`，macOS 的播放没有 CPU 暴涨，切换倍速也不会，排查 bug」。据此撤销 11-03 的 `IOSAudioPlayer` 封装：删除 `View/iOS/App/IOSAudioPlayer.swift`、8 个 iOS 文件引用改回 `AudioPreviewPlayer`、pbxproj 4 处注册行删除。`Shared/Services/AudioPreviewPlayer.swift` 与所有 macOS 调用点全程未动。
- **关键线索**：两端编译同一个播放器类，`updateProgress()` 同样 0.1s 写 `currentTime`/`progress`，倍速同样走 `AVAudioPlayer.enableRate` → 引擎层无平台差异，差异只可能在 SwiftUI 订阅拓扑。上一轮换 `AVPlayer + .timeDomain` 用户验证「CPU 还是暴涨」也反证根因不在音频重采样。

### 根因（macOS 早就修过同一个 bug）
- macOS 三处注释就是现成答案：`View/macOS/HistoryView/AudioPlayerDetailView.swift:16-20`「不要用 @ObservedObject 持有播放器…整页（元信息条、几百字原文区）被拖着重算，这是 CPU 打满的直接原因之一」；`VoiceStudioView/AudioGenerationModal.swift:270-275`「订阅范围一旦上移到弹窗…这就是之前播放时十分卡顿的原因」；`VoiceStudioView/VoiceStudioView.swift:970-976`「把订阅关在这一层…10Hz 只让这一个小小行视图重绘」。macOS 宿主一律 `let player` 不订阅，订阅只在 `PlayerWaveformView` / `PlayerTransportView` / `PlayerUtilityView` / `PlaybackStatusBar` / `VoiceRowPlayback` / `ModalAudioPlayer` 这些几十行小 View；`HistoryView.swift:102` 只传 `isPlaying: Bool`，`Shared/HistoryViewModel.swift:33` 用 `let player` 不转发 objectWillChange。
- iOS history v2 全反了：`RootTabView.swift:29` 根容器订阅（整个 TabView + 3 个 NavigationStack）、`ProjectsView.swift:31` 列表宿主订阅且 `:222` 把 `player.progress` 传给 **ForEach 每一行**、整页 `PlayerDetailView.swift:27`、整个 `GenerationDialog.swift:75`。一次 `objectWillChange` → 全 App 视图树 × N 行重算，每行还跑 `range(of:)` / `rowTime` / `formatDuration` / `VoiceAvatar` FNV 哈希。
- 为什么上一轮静态化波形无效：`StaticWaveformBars` 只挡住一个 Canvas 的绘制，`WaveformScrubber` 外层几何仍 10Hz 重布局，且 `GenerationDialog.swift` 里另有一份随 progress 重绘的 `WaveformBars`；更重要的是 **body 被调用的次数和视图数量一点没少**。

## mini player 进度条圆角溢出
- 现象：进度条左右超出卡片。根因是 `MiniPlayerView` 的进度条在 `scaleEffect` 之后**自己又套了一层** `.clipShape(RoundedRectangle(cornerRadius: 16, style: .continuous))` —— 2pt 高的条用 16pt 连续圆角，裁剪路径会向左右溢出。
- 修法：删掉内层 clipShape，进度条只保留 `Rectangle().fill(.white.opacity(0.85)).frame(height: 2).scaleEffect(x:..., anchor: .leading)`，圆角交给整卡唯一一层 `.clipShape(RoundedRectangle(16))`。与 `HistoryRow`（`RowProgressTrack`）/ `UndoToastView` 的进度条写法完全一致 —— 这是项目统一模式，别再给底部进度条单独加圆角裁剪。
- 验证：`typecheck.sh` 0 error；`bash tools/ios_build.sh` **BUILD SUCCEEDED**。
