## 锁屏封面四角白色楔形（bug 修复）
- 现象（用户截图）：粉色圆角封面四个角外侧有白色三角，底边还有一条更宽的白色横条，整圈细白边；封面里是渐变 + 白色「朔」字。

- ⚠️ 通用坑：锁屏 artwork 绝不能留透明像素、也不能在图片里自绘圆角；圆角由系统统一处理。

## iOS 生成后台接收（WebSocket 保活）
- 需求：`GenerationDialog` 接收音频时按 Home / 锁屏也要继续收流；用户已在 `iOSEmora-Info.plist` 加 `UIBackgroundModes = audio/fetch/processing`。
- ⚠️ **核心结论：这三个 mode 一个都不能让 `URLSessionWebSocketTask` 后台续收**。`audio` 只在真的播放/录制音频时保活（本项目播放器需要它，生成阶段没有 AVAudioSession）；`fetch` = BGAppRefreshTask、`processing` = BGProcessingTask，都是系统择机调度且必须 `BGTaskSchedulerPermittedIdentifiers` + 注册/提交后才存在，接不上当前这条连接。且 `beginBackgroundTask` **不需要**任何 UIBackgroundModes 声明。
- 实现：新增 iOS 专属 `View/iOS/Services/GenerationBackgroundKeeper.swift`（`@MainActor` 单例）：`start()` 在**前台就**调 `UIApplication.shared.beginBackgroundTask`（系统只在真进后台后开始计时，不必等 didEnterBackground）；expirationHandler 回 MainActor 收尾、主动 `closeConnection()`、发本地通知；`finish(success:)` end task + 后台时才发通知。通知走 `.provisional` 静默授权，不弹权限框打断首次生成。
- 驱动：`RootTabView` 用 `.onChange(of: studioVM.isGenerating)` 一次生成只 start/finish 各一次（+ `.onAppear` 幂等兜底）。⚠️ **别挂到单段 synthesizeStream**：多片段会多次建连、反复申请/结束；也别挂弹窗（弹窗关掉生成仍在跑）。
- pbxproj 4 处新 ID：FileRef `7B3A...0E` / BuildFile `7B3A...0F`（`0C` 已被 iOSEmora-Info.plist 占用）；Services group children + iOSEmora Sources 各加一行。

- 边界（未解决）：后台额度通常约 30s（`backgroundTimeRemaining` 实测）；到期后 WebSocket 断且**不可续传**，而 `performSynthesize` 现有容错是「已有分片就不抛错、直接返回」→ 可能落盘半截音频。彻底方案只能是把合成服务端任务化（Edge Function 异步合成 → Storage → 客户端轮询/静默推送），配合 BGTaskScheduler；本次未改这段容错语义（macOS 共用）。

- 全项目「滚动收键盘」只有两条入口，逐一堵上：
  * `StudioView` 宽屏（两栏 / iPad）分支的 `ScrollView` 原本是 `.scrollDismissesKeyboard(.interactively)` —— 编辑器就嵌在这个 ScrollView 里，`interactively` 会让键盘跟着拖拽手势被推走（正文短、编辑器自身滚不动时只滚页面也一样）。改为 `.never`；收键盘只留显式出口（底部「完成」/ `onDisappear` 的 `finishEditing` / 生成前收口）。
  * `TokenTextEditor.makeUIView` 新增 `tv.keyboardDismissMode = .none`：`UITextView` 本身是 `UIScrollView`，显式写死，不依赖 UIKit 默认值（避免被将来的 `UIScrollView.appearance()` 全局配置带偏）。
- ⚠️ 教训：给「编辑器所在页面」的 ScrollView 挂 `.interactively` 等于把「滚动浏览文本」和「收键盘」绑在一起；编辑器类页面一律 `.never`。窄屏分支本来没有 ScrollView，所以 iPhone 竖屏若仍复现，下一步查 UIKit 侧 `keyboardDismissMode` 是否被别处改写。
- 验证：`bash tools/ios_typecheck/typecheck.sh` 0 error（仅存量 warning）。

## VoiceAvatar 配色：8 组固定色板 → 程序化生成（去重）
- 问题：`VoiceAvatar.gradient(for:)` 只有 8 组色对轮换，599 个音色平均每组撞 75 次，一屏 20 个必有大量同色；且旧色板亮蓝/亮黄/亮粉上白字对比度只有 1.4–2.1。
- 改法（`View/iOS/DesignSystem/AuroraComponents.swift`，仅 iOS）：删 `palettes`，改为 seed 确定性生成。
  * 色相：`(h % 1024) * 137.508`（黄金角，相邻哈希散到色环两端）后再过 `baseHue(for:)`，**跳过 38°–85°（黄→黄绿）**——白字在那个区间任何明度都只能压成橄榄/土黄。
  * 饱和度 0.78–0.94；明度查 24 档 `brightnessCurve`（0.62…0.88 夹紧）+ ±0.03 抖动。曲线按「渐变中点 vs 白字对比度 ≈3.3:1」离线反解得出，写在注释里。
  * 渐变仍是「上浅下深」：顶部 `sat*0.84 / bri+0.11`、底部 `sat / bri`，色相各偏 5°。
- 度量（用 599 个真实 key 跑）：唯一中点色 595/599（旧 8）；白字对比度 2.7–8.0 均 3.8；一屏 20 个近似对(ΔE<6) 中位从 24 降到 4，最小 ΔE 中位 0→1.8。
- ⚠️ 调参注意：明度上限不要放回 0.99 —— 紫/蓝/粉色相的曲线值本就是 1.0（这些色相天生暗），不夹到 0.88 会让顶部与底部几乎同色、渐变糊平。
- 验证：Swift 复算与 Python 预览逐 seed 十六进制完全一致；`typecheck.sh` 0 error；`ios_build.sh` **BUILD SUCCEEDED**。
- 未动：macOS `View/macOS/Components.swift` 的 `resolvedGradient`（6 组低饱和，另一套 UI，需要时再同步）。

### 更正（同日）：需求其实是「滚动 → 收键盘」，方向反了
