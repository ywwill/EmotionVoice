### 关键结论（后续修复时的锚点）

- **P0-1 密钥泄漏**：`Services/RegionConfig.swift:37,44` 明文存阿里云 `sk-ws-...`，
  `Helper/Const.swift:13` 存 Supabase publishable key。已确认进 git 历史：
  HEAD 里是旧 key `sk-964c3945bd89460f976f6b8bf13442b7` / `sk-557be4f42f724dd0848c08bc20f89c05`
  （说明轮换过一轮但没换存储方式）。需吊销 + `git filter-repo` 清理。
- **P0-2 积分可篡改**：`SupabaseManager.updateCredits()` 用 publishable key 直接 upsert
  `user_credits.credits`，客户端即权威，必须改服务端 RPC。
- **P0-3 同步失败静默**：`CreditManager.deduct/syncFromCloud` 失败只打日志，
  导致「内购蒸发」和「断网白嫖」双向漏洞。
- **P0-4 沙盒无 entitlements**：`ENABLE_APP_SANDBOX = YES` 但工程里没有 `*.entitlements`，
  `CODE_SIGN_ENTITLEMENTS` 为空 → 缺 network.client（联网可能被拒）与
  files.user-selected.read-write（导出目录权限）。需 Release 包实测。
- **P1-5 TTS 死循环**：`BailianTTSService.waitForTaskStarted()` 无超时 + `reconnectAndReceive()`
  重连后不重发 run-task → 永久挂起；`AsyncMutex` 串行化会把后续所有请求一起堵死。
- **P1-6 取消是假的**：`VoiceStudioViewModel.generate()` 的 `Task{}` 无句柄，
  `cancelGeneration()` 不 cancel → 协程泄漏 + 可能照常扣费。
- **P1-7 多扣费**：`estimatedPoints` 用 `text`（含 token 中文 label 装饰字）而非 `plainText`。
- **P1-11 DB 无迁移**：`createTables()` 全 `ifNotExists`，代码中**不存在**
  `resetDatabaseIfSchemaChanged` / `currentSchemaVersion`（MEMORY.md 里记的策略已不在代码里）。
