## 语言 chip 不再写入自然语言指令输入框（macOS + iOS）
- 需求：macOS `VoiceStudioView` / iOS `StudioParamSheet` 选语言后，指令输入框不该被填入文字。
- 根因：共用 VM `VoiceStudioViewModel.updateNLInstruction()` 把 `selectedLanguage?.localized()` + 预设指令一起拼进 `nlInstruction`，`toggleLanguage()` 与 `applyPreset()` 都调它。
- 改动仅一处 `Shared/ViewModels/VoiceStudioViewModel.swift`：`toggleLanguage()` 去掉 `updateNLInstruction()` 调用；`updateNLInstruction()` 只写 `selectedPreset` 的 `instruction?.localized()`，移除语言项与 `AppLanguage.isChinese` 分隔符逻辑（否则「先选语言、再点预设」语言名仍会漏进输入框）。
- 语言功能未受影响：`selectedLanguage` 仍经 `Constants.languageHint(forName:)` 传给 `synthesizeWithTimeline(languageHint:)` 的 `language_hints`。预设行为不变（选中填指令、取消清空）。三份 strings 的语言名译文仍用于 chip 显示 `lang.name.localized()`，不用改本地化文件。
- 验证：`tools/ios_typecheck/typecheck.sh` exit 0（5 条既有 warning，与本次无关）；`tools/ios_build.sh mac` 双 target BUILD SUCCEEDED。

## macOS 批量删除后自动退出编辑（多选）态
- 需求：历史列表批量选择并删除后，应自动取消编辑状态。
- 根因：`View/macOS/HistoryView/HistoryView.swift` 的 `deleteSelected()` 末尾只 `selectedAudioIds.removeAll()`，`isSelectionMode` 仍为 true → 批量操作栏留着「0」、行首勾选框还在，需再点一次「取消」。
- 改动：末尾改为调用现成的 `exitSelectionMode()`（同时置 `isSelectionMode=false` + 清选中集）。⚠️ `NowPlayingMiniStore.shared.clearIfMatches(selectedAudioIds)` 必须在它之前调用，否则传入的集合已被清空；顺序保持原样。
- 未改动：批量导出后仍保留编辑态（用户只要求删除）；编辑模式下单条右键删除不会同步从 `selectedAudioIds` 移除该 id（相邻遗留问题，计数可能虚高）。
- 验证：单独 `xcodebuild -scheme Emora -sdk macosx` BUILD SUCCEEDED（37s，沿用 `-disable-sandbox` + `IDEPackageSupportDisableManifestSandbox` workaround，退出时恢复原值）。`tools/ios_typecheck/typecheck.sh` 不覆盖 macOS 文件，本次不适用。

## macOS 批量导出三处修复（同一文件 `View/macOS/HistoryView/HistoryView.swift`）
- ① 导出后退出编辑态：上一节「批量导出后仍保留编辑态」已修复。NSOpenPanel **取消时保留**编辑态（用户可能换目录重试），只有 `.OK` 后退出。
- ② 同名不再覆盖：旧 `exportSelected()` 遇同名先 `removeItem` 再 `copyItem`，同一批里后写的覆盖先写的，且会**删掉目标目录里用户原有的同名文件**。现新增 `uniqueExportURL(for:in:reserved:)`：`name.ext` → `name (2).ext` → …，`reserved` 记本批已分配 + `fileExists` 查磁盘，key 用 `lowercased()`（APFS 大小写不敏感）；`/`、`:` 替换成 `-`；`copyItem` 前**绝不 removeItem**。
- ③ 单条「更多 → 导出」误起播：根因是 `audioRow.onExport` 调了 `viewModel.selectAudio(audio)`，而 `HistoryViewModel.selectAudio()` = 设 `selectedAudio` + `playAudio()` 起播。现只调 `exportAudio(audio)`（它只用参数、不依赖 selectedAudio）。
- ⚠️ NSOpenPanel 回调是异步的，里面要调 MainActor 隔离的 `@State`/VM：沿用同目录 `PlaybackKeyboardShortcuts` 先例，用 `MainActor.assumeIsolated { self.exportAudios(...) }` 把写盘与 `exitSelectionMode()` 整体收进来，避免 Swift 5 默认 MainActor 下的并发告警。`selectedAudios` 在 `begin` 之前做快照，面板期间选中集变化不影响导出内容。
- 未改动：单条导出 `HistoryViewModel.exportAudio()` 走 NSSavePanel，用户自己确认替换，不属于批量同名问题；编辑模式下单条右键删除仍不会同步清 `selectedAudioIds`（遗留）。
- 验证：`xcodebuild -scheme Emora -sdk macosx` BUILD SUCCEEDED，0 error、0 条新增 main actor/Sendable 告警；`swift -e` 真实写盘冒烟：目标目录预置 `same.mp3`(ORIGINAL) + 3 个同名导出 → `same (2/3/4).mp3`，三份内容各自完整、原文件未被删改，大小写/斜杠冒号/无扩展名场景通过。
