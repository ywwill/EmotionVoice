## 第十三轮：iOS 输入框标记行为 + 播放器拖动 + 列表滚动

### ① StudioView 输入框：拟声标签退格删除
- **根因**：`TokenDocument.adjust` 的拟声分支判定写成 `mark.location > editedRange.location`。
  退格删掉占位符本身时 `editedRange` 的**起点正好等于**标记位置（`range.length == 1`），
  于是既不算「落在区间内部」，也没走到平移分支，直接 `return mark` —— 字符没了、标记留下，
  变成一枚没有字符可依附的孤儿标记（虚线 pill 消失但 × 还挂着）。
- 修法：`>` → `>=`。补了 5 条断言覆盖四种编辑方向（删前 / 删自身 / 整段删 / 插入 / 删后）。

### ② StudioView 输入框：中断标签空作用域自动移除
- `pruneEmptyScopes` 原来**只处理 `.emotion`**（注释写「中断是切段边界，空作用域有意义」）。
  但用户明确要求：两个标签中间的中断，其作用域内文本删完后 UI 也要跟着走。
- 改成同时处理 `.emotion` + `.interrupt`（拟声仍交给 `adjust`，因为它占 1 个字符）。
- 效果：顺带缓解了「中断徽章与相邻语气胶囊粘连」—— 中间文本删空后中断标记直接消失。

### ③ StudioView 输入框：中断 ↔ 语气接缝收敛改可靠实现
- `applyInterruptGaps` 原来是「矩形端点匹配」（`abs(a - textRect.maxX) <= 1.5`），
  容差脆弱，行首 / 行尾 / 跨行切段时容易漏判。
- 改为**基于文档位置推导**：沿 `orderedMarks` 找中断的前后邻居（左邻取最后一段，
  右邻取第一段），再对对应盒段收窄 / 推移，不再依赖端点浮点相等。

### ④ PlayerDetailView：拖动频谱卡顿
- 原实现在 `DragGesture.onChanged` 里**每帧 seek**，播放中拖动会让解码器反复丢弃
  已缓冲数据重建，实测掉到 20fps 以下。
- 改法：`WaveformScrubber` 的 `onSeek` 拆成 `onScrubStart` / `onScrubEnd` 两个回调。
  - 按下的那一刻：若正在播放则 `pause()`，并记下 `resumeAfterScrub`；
  - 拖动中：**只更新本地 `dragging` 跟手，不 seek**；
  - 松手：seek 一次到落点，若 `resumeAfterScrub` 则 `resume()`。
- 声音落定到松手时那一次，因此拖动丝滑且不会出声撕裂。
- ⚠️ 一次拖动只暂停一次：用 `didNotifyStart` 门控，`onEnded` 里复位。

### ⑤ ProjectsView：左滑「复制」动画再优化
- 副本插在列表**顶部**（`allLoadedAudios.insert(copy, at: 0)`，按创建时间倒序）。
  用户在列表中下部操作时，新行出现在屏幕外，只看得到整列往下跳 —— 这才是「动画不好」的真实来源。
- 改法：`List` 外包 `ScrollViewReader`，每行 `.id(audio.id)`；
  插入后用缓动动画 `scrollTo` 第一行，把「跳动」变成「新行从顶部长出来」。
- 保留（并略微缩短到 220ms）的延迟，避免左滑菜单收起与列表插入在同一帧抢同一个 row。

### ⑥ VoicesLibraryView：滚动后收藏「没反应」
- 上一轮用 `ScrollViewReader` + 顶部 0 高锚点 + `scrollTo`，**实测仍未生效**。
  根因是时序：`scrollTo` 在布局前按**旧 contentSize** 计算偏移，行数变少时算出的偏移仍超出新范围。
- 改法：弃用 `scrollTo`，改成给 `ScrollView` 挂 `.id(scrollResetID)`；
  `reload()` 里 `scrollResetID += 1` → ScrollView **整体重建** → contentOffset 必然归零。
  （顺便删掉了 `scrollProxy` / `topAnchorID` / `scrollToTop()` 一整套。）
- 分类切换走 `CategoryFilterSheet.onCommit → reload()`，因此同样受益（满足「切换分类自动滚到最上面」）。
- `VoicePickerSheet` 是同一份拷贝，同步改成 `.id()` 方案。

### ① 致命 bug：插入第二个语气标签 → 打字 → 标签被吃掉、文本并进第一个标签
- **根因**：空作用域回收。`pruneEmptyScopes` 在 `textViewDidChange` 里**当场**删掉作用域为空的
  边界标记，门控只是一个布尔量「本次编辑删过字」。两条真实路径会误伤：
  * 中文输入改候选词 = 「先删掉上屏的字 → 再插入新候选」两步。第一步落地时，
    刚插入的第二个标签（位于文末、作用域天然为空）被当场回收，第二步的字于是整段并进第一个标签；
  * 先插好第二个标签，再回头删第一段里的一个错字 —— 布尔量只判「有没有删过字」，连带回收。
- **修法（判定与回收拆开 + 延迟结算）**：
  1. `TokenDocument.pruneEmptyScopes` → **`boundaryEmptiness(marks:doc:) -> (empty, nonEmpty)`**，只判定不回收；
  2. `Coordinator` 在 `shouldChangeTextIn` 里把删除**之前**的 `nonEmpty` 存为 `pruneBaseline`；
  3. 每次编辑重置一个 `Task` 定时器，停手 **0.4s** 后才 `settlePrune()`；
  4. 结算条件收紧为「删除前非空 ∩ 现在为空」，且 `markedTextRange != nil`（还在 Composing）时顺延；
  5. `clearAll` 里把待结算任务取消。
- ⚠️ 结算延迟用 `Task { @MainActor in try? await Task.sleep }` 而不是 `DispatchWorkItem`：
  GCD 的 `@Sendable` 逃逸闭包在 Swift 6 下调不了 `@MainActor` 方法（工程里已有同类报错）。
- `/tmp/ev_sim`（含新旧两套逻辑的 Coordinator 仿真）验证：
  场景1/2 旧逻辑丢第二个标签、**新逻辑保留**；场景3/4（真删空、删到什么都不剩）两者一致仍回收。

## 第二轮（标记回收重写 / 胶囊让位 / 拟声居中 / 左滑复制）

### ① StudioView 输入框：标记回收的判据彻底换成状态机
- 上一轮那版「记一次删除前快照 + 0.4s 后结算」仍然被试出来的两个场景打穿：
  * 插第二个语气标签 → 打字 → 标签消失、文本并进第一个标签；
  * 标签里的字删光了 → 标签还赖着不走。
- 根因：判据里掺了**时序信息**（「这次编辑删没删东西」+ 一张延迟快照），同一段操作
  在不同节奏下得到不同结果。现在改成**每帧更新状态、只认 `非空 → 空` 翻转**：
  * `TokenDocument.isBoundary` + `boundaryEmptiness` 只提供当前状态（新增前者为 `nonisolated static`）；
  * Coordinator 持有 `scopeHadText: [UUID: Bool]` / `pendingRemoval: Set<UUID>`，
    `refreshScopeStates()` 挂在 `tvDidChangeContent` 最前面 —— 打字 / 插标签 / 删标签 / 清空
    **每条路径都跑同一遍判定**（早先只挂在 `textViewDidChange` 上，时序会错位）；
  * 从未有过内容的标签**永远不会被自动回收**（根治场景①）；有内容被删光必然翻转一次（场景②）。
  * 重新捞回文本时 `pendingRemoval.remove(id)` 撤回待回收，0.35s 后才真正删。
- `/tmp/tksim`（Coordinator 状态机 1:1 仿真）8 条用例全绿：
  S1 中文候选上屏后的第二个标签保留、S2 空作用域标签被误删修复、S3/S5/S6 三种「删光」、
  S4 删光又立刻重打保留、S7 拟声占位符由 `adjust` 回收、S8 连续打字不掉标签。

### ② 中断后的新语气标签：给「没有底色的邻居」让位

## 第三轮：语气/中断标记占位化（给胶囊造出左右内边距）

### 背景
「语气标签里的文本紧贴标签边缘」的根因不是绘制代码，而是**iOS 的语气/中断标记是零宽的**：
两段文本在排版上严丝合缝，`capsulePadX` 只能靠**侵入邻居**或**在接缝处把另一侧按到文字边界上**
换空间 —— 于是右侧内边距恒为 0（上一轮的 `applyNeighborGaps` / `applyInterruptGaps` /
`resolveSeams 语气支` 都是这套补偿的产物）。macOS 同一个标记是 5×1 的可见占位，天然有空隙，
从来没这个问题。

### 改动
1. **三类标记统一占 1 个 U+FFFC 占位**（`InlineSpaceAttachment`，原 `SoundPlaceholderAttachment`）：
   - 语气/中断占 `toneSpacing = 14pt` 空白（高 12，别超过正文字高否则 TextKit 撑高行）；
   - 拟声仍占 `pillWidth + 2×pillSpacing`。
   - `TokenDocument.adjust` 于是只剩一条规则（占位符被换掉 → 标记没），零宽那条
     「夹回区间起点」分支连同 `boundaryEmptiness` 的 start 改成 `location + 1` 一起删掉。
   - `contentItems` / `make` 对所有占位标记统一 +1 跳过；`plainText` 本来就剔除 U+FFFC。
   - 插入后**光标必须跳到占位符之后**（`insertPlaceholder`），否则打字会落在作用域之外。
2. **绘制层**：`TokenCapsuleOverlay` 删掉 `applyInterruptGaps` / `applyNeighborGaps` /
   `isCovered` / `glyphRunRect` / `SeamBox.charRange`；`linePieces` 退回 `lineRects`（不再返回
   字符区间）；`resolveSeams` 只保留 pill 一支；`capsulePadX 8→6`、新增 `toneSpacing`。
   - 几何：占位 14pt → 左右各 6pt 内边距、相邻两标签留 2pt 缝；约束 `capsulePadX × 2 < toneSpacing`。
   - 徽章锚点用 `location + 1`（占位符之后那个位置，也就是接下来要打字的地方）。

### 验证

### 13:20 键盘弹出时进二级页 → 返回后底部条消失

## 第四轮：相邻语气标签的首尾缝隙（收缝回到绘制层）

### 现象
上一轮把语气 / 中断改成 14pt 占位后，单个标签的左右内边距正常了，但**两个语气标签连着时，
第一个的末尾和第二个的开头重叠**。

### 根因（用 AppKit 复刻 TextKit 布局实测，见 `/tmp/tkgeo/geo4c.swift`）
```
toneSpacing=14  text1=[14.00, 93.38] text2=[107.38,186.75] 物理缝=14.00 → capsule 可见缝(pad6)=2.00
```
相邻两个标签之间**只有一份 14pt 占位**，要同时支付「前一个胶囊的右 pad 6 + 后一个的左 pad 6」，
剩 2pt，再被两条 1pt 描边各吃掉 0.5pt → 肉眼只剩 1pt，圆角 9 的两个圆角在那里就是「重叠」。
（顺带修正：早先把 `applyInterruptGaps` / `applyNeighborGaps` 全删是对的，但「语气 ↔ 语气」
这一支当时也一并删过头了 —— 物理空隙不够，仍需绘制层补一刀。）

### 改动（`View/iOS/Views/Studio/TokenCapsuleOverlay.swift`）
- `Config` 新增 `capsuleSeamGap = 6` / `capsuleMinPad = 3`。
- `resolveSeams` 拆成两支：`cutToneSeam`（不同标记的胶囊，从两侧各匀一点把缝撑到 6pt）
  与 `cutPillSeam`（原 pill 分支，逻辑不变）。
- ⚠️ `cutToneSeam` 的让位量按 `slack − minPad` 截断，**pad 到 3pt 就停手** ——
  这是不再复现「为了让缝隙把文字顶到边缘」的关键（早年那几版没有地板）。
- 同标记的多个片段（被拟声 pill 切成几截）不参与收缝。

### 验证
`/tmp/tkgeo/seam.swift`（同构仿真，真实 NSLayoutManager 量出的矩形）四场景：
```
两个相邻语气标签      缝 6.00  pad 6/4 与 4/6
三个连续语气标签      缝 6.00 / 6.00，中间那个 4/4
单个标签（裸文本相邻） 完全不被动，pad 6/6   ← 上一轮的成果没有回归
语气 / pill / 语气     pill 缝仍 3.00（原行为不变）
```
`tools/ios_typecheck` 0 error；`ios_build.sh ios` + `mac` 双 BUILD SUCCEEDED，0 新告警。
⚠️ 仍需真机目视：若嫌 6pt 太宽调 `capsuleSeamGap`，嫌文字离边太近调 `capsuleMinPad`（≤ padX 6）。

### 15:30 底部条与键盘 accessory 重叠 → 改成实测让位
- 需求：键盘弹出时「完成 / 生成音频」不能压到 `EmotionAccessoryBar`，距离 0 可以。
- 不能用常量：通知里的 `keyboardFrameEndUserInfoKey` 有时是纯键盘、有时才带 accessory，
  SwiftUI 的键盘避让跟着忽大忽小 → 差值必须实测。
- 实现：`TokenTextEditor` 新增 `onKeyboardTopChanged`，Coordinator 订阅
  willChangeFrame / didChangeFrame / didShow（willHide 传 nil），顶边取
  `min(键盘框 minY, accessory 窗口框 minY)`；`deinit` 里移除观察者。
  `StudioView` 用 background 的 GeometryReader 量内容底边（global maxY − safeAreaInsets.bottom），
  差值 = `keyboardSeam`（夹 0~260），加在 `generateBar` 底部 padding。
  ⚠️ 只在 `onPreferenceChange` 里算（布局量完之后），且键盘框不在屏内就放弃测量。

### 15:50 accessory 副行（标签描述）不显示
- 症状：点语气 / 拟声标签后，标签条底部那行描述看不到。
- 根因：`AccessoryContainerView` 的高度是写死的 116（`intrinsicContentSize`），
  副行是**追加**在这 116 之外的一行；且 UIHostingController 的根视图在固定高度的容器里
  **默认居中** → 副行被顶到容器边界外被裁。
- 修法三条：
  1. 副行**常驻**（没选标签时显示当前分段说明），不再「有才加一行」→ accessory 总高恒定 116，
     键盘不会随点标签上下跳；高度区 `hintHeight = 34`。
  2. 高度改自适应：SwiftUI 用 `background(GeometryReader)` + `AccessoryHeightKey` 上报实测高，
     `AccessoryHost` 用 Combine 订阅 `config.$contentHeight` → `container.contentHeight`
     （setter 里 `invalidateIntrinsicContentSize`，键盘系统只在 intrinsic 变化时重排）。
  3. 根视图 `.frame(maxWidth: .infinity, maxHeight: .infinity, alignment: .top)` 顶对齐，
     多余高度留在底部（居中会让副行往下飘贴着键盘边）。
- 描述内容：`AccessoryHint(item:)` 里 label/description 相同时只显示名字（「大喊 · 大喊」看着像没显示）；
  顺手补全了 Constants 里 5 条与名字完全重复的描述（大喊 / 大笑 / 咯咯笑 / 清嗓 / 咳嗽）。
- accessory 高度变化（未来副行换行 / 动态类型）会回调 `AccessoryHost.onHeightChanged` →
  Coordinator 用缓存的 `lastKeyboardFrame` 重算一次顶边，底部让位量跟着变。

### 16:05 「生成音频」按钮改固定宽度
- `PrimaryButton` 加 `width: CGFloat?`：非 nil 时 `.frame(minWidth: width, maxWidth: width ?? (isFullWidth ? .infinity : nil))`，
  padding 归 0，文字 `.lineLimit(1).minimumScaleFactor(0.8)`（英文 Generate Audio 比中文长一截，不缩放会被切）。

### 16:35 去掉 accessory 副行，改「插入后弹临时提示」

### 16:55 accessory 底部到键盘之间的空白（30pt）
- 根因：`EditorAccessoryConfig.baseHeight` 还停在 116（副行 34 已不在 body 里），而容器
  `AccessoryContainerView` 是手写 frame 建的（`translatesAutoresizingMaskIntoConstraints` 把 frame
  翻成宽/高约束）→ 键盘只在弹出那一刻量一次高度，`invalidateIntrinsicContentSize()` 改不动 frame
  → accessory 永远 116，内容 86 顶对齐，下面 30pt 空白。
- 修：① 新增 `AccessoryMetrics`（top 6 / 控制行 42 / 标签行 38 → baseHeight 86），三处初始值

  ② `contentHeight.didSet` 里**自己改 frame** + `superview?.setNeedsLayout()`（光 invalidate 不够）；
  ③ `AccessoryContainerView.safeAreaInsets` 覆写成 `.zero`（键盘窗口的 bottom inset 会渗给 SwiftUI，
  内容被顶上去也是同一症状）。
