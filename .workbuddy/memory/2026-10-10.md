## 追加修订（同日）

用户反馈两点：

1. **删除无限旋转动画** —— `RotatingRing` 结构体及其在 `generatingContent` 的调用已整体移除，图标区只剩静态圆形底 + ⚡。写入头的呼吸脉冲（`AccumulatingWaveform.headGlow`，0.72s 往复）刻意保留，它表达"正在接收"，不是装饰性转圈。

2. **累积曲线起步太快** —— 根因：项目默认 `Constants.defaultFormat = "wav"`、`defaultSampleRate = 48000`，10 秒 wav 就有约 960KB。原对数曲线（参考上限 2048KB）在只收到 10% 数据时就显示到 60%，所以"看着快满了但还有大量数据没来"。
   修改：
   - 新增 `enum AccumulationCurve`（替代原 `accumulationFill(for:)` 私有函数），参考上限降到 1024KB，并对归一化后的对数取 **1.35 次幂**压低前段。
   - `fill(bytes:timeProgress:)` 与 `vm.generationProgress`（VM 按"已耗时/预期时长"算的进度）**取小值**——谁保守听谁的。大文件时由时间轴兜底、小文件时由字节曲线兜底。
   - `AudioAccumulationMonitor` 增加 `progress` 入参，调用处传 `vm.generationProgress`。
   - 效果（1MB wav）：10% 数据时显示 60.5% → 14.0%；50% → 50.0%；完成时 93.6%。
   - 若想回到纯字节驱动，把 `fill(bytes:timeProgress:)` 里的 `min` 去掉即可（已在注释里写明）。

调参旋钮：`AccumulationCurve.referenceKB` / `exponent` / `ceiling`。
预览 `AccumulationAnimationPreview` 已改为模拟 ~90KB/s 的 wav 吞吐 + 11 秒时间轴，可直接跑终局观感。

## 累积动画第三次改版：波形 → 水滴累积池（当前版本）

用户反馈：横向波形图"始终有结尾"，但流式返回根本不知道何时结束，要求换成「水滴一直累积」的隐喻。

实现（`Views/VoiceStudioView/AudioGenerationModal.swift`）：
- 删除 `AccumulatingWaveform`（56 根波形条 + 写入头的横向填充形态），彻底去掉横向进度语义。
- 新增 `WaterDrop` / `WaterFieldMetrics` / `WaterDropField`：
  - `TimelineView(.animation(minimumInterval: 1/30))` + `Canvas` 自绘，**没有 `repeatForever`**，全部动态由 `birth` 时间戳推导，避免 SwiftUI 无限循环动画。
  - 每滴水：0.5s 自由落体（`easeIn` 二次方加速）→ 入水后 2.0s 扩散 3 圈同心椭圆涟漪（半径 0.46×池宽，`pow(1-cycle,1.7)` 淡出）→ 超过 `lifetime=2.8s` 回收。
  - 水面用两道不同波长的正弦叠加（λ=150 / λ=82，反向流动）持续起伏，相位差 1.8 的淡影做厚度。
- `AudioAccumulationMonitor` 改为：12pt 高的水池（`.frame(height: 120)`）+ 水滴图标的字节数 + 速率 + 绿点。
  - 新增 `poolCeiling = 0.82`：水位永远不满，不给"快好了"的暗示。
  - 新增 `targetDropsPerSecond = 8`：`bytesPerDrop = speed/8`，按实时吞吐自适应折算水滴，不同体量音频视觉密度一致；限流条件 `drops.count < 14`、`间隔 ≥ 0.07s`。
  - `level = AccumulationCurve.fill(bytes:displayBytes, timeProgress:progress) * 0.82`。
- `VoiceStudioView.modalHeight` 生成中 500 → 550。
- `#Preview("音频数据累积动画")` 放在 `AudioAccumulationPreview` 之后，可用 Xcode Canvas 调参。

调参旋钮：`WaterFieldMetrics`（fallDuration / rippleDuration / maxRippleRadius / rippleRings / maxActiveDrops）、`poolCeiling`、`targetDropsPerSecond`。

### 水滴累积池微调：去掉同心波纹（2026-10-10 追加）

用户要求：水滴落到水面后不要出现一圈圈荡开的波纹。

修改：
- `drawImpact`（同心涟漪 3 圈，`maxRippleRadius = 0.46×池宽`、`pow(1-cycle,1.7)` 淡出）整体删除，改为 `drawSplash`。
- `drawSplash`：入水点原地亮起一小片椭圆水花（半径 2.0 → 5.6，高度 = 半径×0.62，`pow(1-cycle,1.6)` 淡出），
  再叠一缕向上溅起随即落回的细水柱（前 60% 时长，高度 3.0 → 8.0）。**只有"溅起—落下"，没有向外扩散的圈。**
- `WaterFieldMetrics` 删掉 `rippleDuration` / `maxRippleRadius` / `rippleRings`，改为 `splashDuration = 0.34`；
  `lifetime = fallDuration + splashDuration = 0.84s`（原来 2.8s），水滴回收更快，同屏密度上限 14 现在远达不到。
- 同步更新 `WaterDropField` 的文档注释（说明为何不画波纹）。

### 生成弹窗高度自适应（2026-10-10 追加）

问题：接收数据时弹窗高度写死 550，卡片内容只有约 434，底部空出一百多 pt。

方案：**用 PreferenceKey 实测各区块高度求和**，不再写死常量。

- 新增（在 `#Preview` 之后、`// MARK: - 音频生成弹窗` 之前）：
  - `MeasuredHeight: PreferenceKey`，Value 为 `[String: CGFloat]`，`reduce` 用 `merge` 保留新值；
    用 tag 区分区块，避免多个 `background(GeometryReader)` 互相覆盖。
  - `MeasureHeight: ViewModifier`（`content.background(GeometryReader { .preference(...) })`）+ `View.measureHeight(_:)`。
  - `enum ModalHeightTag { header / footer / generating / completed }`。
- `AudioGenerationModal` 新增：
  - `@Binding var preferredHeight: CGFloat`（回调给外层 sheet；唯一调用点在 `VoiceStudioView`，已同步改成传 `preferredHeight:`）。
  - `@State headerHeight=61 / footerHeight=71 / generatingContentHeight=303 / completedContentHeight=450`（初值取经验值，避免首帧跳动）。
  - `static let contentMaxHeight = 460`（完成态常见高度约 450，正好不触发滚动）、`minCardHeight = 200`。
  - 计算属性 `visibleContentHeight`（内容实测值，夹在 0…contentMaxHeight）与 `cardHeight = header + content + footer`。
  - 卡片 `.frame(width: 520, height: cardHeight)`；内容 `Group` 加 `.frame(height: visibleContentHeight)`；
    header/footer/两个 ScrollView 内层 VStack 各打一个 `measureHeight(tag)`；根节点 `onPreferenceChange(MeasuredHeight.self)` 回填。
- 关键点：**cardHeight 只由各区块实测值决定，与外层给出的高度无关**，因此不存在循环布局；
  header/footer 高度恒定，外层高度变化不会引发二次测量。
- `VoiceStudioView` 删掉 `modalHeight` 计算属性，换成 `@State generationModalHeight = 434`，
  sheet 内 `.frame(width: 520, height: generationModalHeight)` + `.animation(.easeInOut(0.35), value:)`。

### 高度自适应方案的 bug 修复（2026-10-10 追加，最终版）

上一版「实测各区块高度求和 + 反向驱动外层 sheet 窗口高度」引出两个动画问题，已回滚该方案：

1. **初始化时内容"从卡片外移动进来"**
   根因：`visibleContentHeight` 依赖 `@State` 初值（303/450/61/71，是我拍的经验值）。
   首帧布局后 PreferenceKey 回填实测值 → 数值变化 → 根节点那条
   `.animation(.easeInOut(duration: 0.35), value: cardHeight)` 把这次**修正**当成了真正的高度变化，
   于是卡片与内容在 sheet 滑入的同时又飘了一下。
2. **结束时卡顿的高度变大动画**
   根因：卡片高度 434 → 581 会通过 binding 改变外层 sheet 窗口高度。
   **macOS sheet 的窗口 resize 不走 SwiftUI 动画时间线，会硬跳一下。**

**最终方案：不再改外层窗口高度，也不再动画高度。**
- 外层 sheet 恢复固定 `520 × 600`（`VoiceStudioView.generationModalHeight`），删除 binding / `@State` 回填，
  `AudioGenerationModal` 的 init 恢复成 `(vm:isPresented:)`。
- 卡片**不给显式高度**（只 `.frame(width: 520)`），由 SwiftUI 自行撑开。
- `ZStack(alignment: .top)`：卡片固定在上边缘向下生长，两态切换时头部不上下窜。
- `generatingContent` **去掉 ScrollView**：生成中是定高短内容，ScrollView 会吃掉全部剩余高度，
  正是"卡片撑满 + 底部留白"的元凶。
- `completedContent` 保留 ScrollView，但显式 `.frame(height: completedScrollHeight)`
  = `min(实测内容高度, 460)`，内容短则收缩、超长则内部滚动。
- 删除 `.animation(..., value: cardHeight)`；只保留 `isGenerating` / `isCompleted` 的动画。
- `MeasuredHeight` 简化为单值 `CGFloat` Key（去掉 tag 字典机制），`measureHeight()` 无参；
  `onPreferenceChange` 里 `if height > 0` 才更新，避免完成态分支不在层级时回落成 0 把卡片压扁。

**经验**：macOS 上不要试图让 sheet 窗口跟随内容伸缩；让内部卡片自适应 + 窗口固定，才是无卡顿的做法。

### 生成弹窗改为整窗 overlay 承载（最终定稿）

用户反馈的两个空白问题：
1. 接收数据时内容高度小，卡片下方露出一大段黑色空白；
2. 接收结束后底部仍有一小段空白。

根因：**只要用 `.sheet` 承载，窗口高度就是固定的**。卡片再怎么贴合内容，卡片下方都会露出遮罩的黑色区域
（接收中卡片约 436 / 窗口 550，完成后卡片约 581 / 窗口 600 —— 两条空白分别对应这两个差值）。
之前尝试「让 sheet 窗口跟随内容伸缩」又会触发 macOS 窗口 resize 卡顿，两条路都不通。

**最终方案：弹窗改用整窗遮罩的 `.overlay` 承载，卡片在遮罩内按内容自行撑开并居中。**
窗口尺寸全程不变 → 无 resize 卡顿；遮罩均匀铺满 → 卡片周围是连续的遮罩，不存在"下方空白"的观感。

具体改动：
- `VoiceStudioView`：删掉 `.sheet(isPresented: $showGenerationModal)` 与 `generationModalHeight` 常量，
  改为在 `studioContent` 上 `.overlay { if showGenerationModal { AudioGenerationModal(vm:isPresented:) } }`，
  配 `.transition(.opacity)` + `.animation(.easeInOut(0.25), value: showGenerationModal)`。
  原 HStack 内容抽成 `private var studioContent`，并加 `.frame(maxWidth: .infinity, maxHeight: .infinity)`
  —— 必须撑满所在区域，遮罩才能铺满整个窗口；两列高度仍是内容自身高度并垂直居中。
- `AudioGenerationModal`：卡片**不给显式高度**（只 `.frame(width: 520)`），由 SwiftUI 自行撑开并居中；
  ZStack 改回默认居中对齐。
- 补 `.onExitCommand { if !isGenerating { isPresented = false } }`：改用 overlay 后不再有 sheet
  自带的 Esc 关闭，这里补回来。

**经验（macOS 弹窗高度）**：
- 不要让 sheet 窗口跟随内容伸缩 —— macOS 窗口 resize 不走 SwiftUI 动画，必卡。
- 也不要让卡片去填满固定高度的 sheet —— 内容一短就露黑边。
- 正解：整窗 overlay 遮罩 + 卡片内容自适应居中。
- `ScrollView` 在容器里会吃掉全部剩余高度，凡是"定高短内容"都不要套 ScrollView，否则卡片被撑满。

### 修复鼠标光标显示 I-beam 竖线（2026-10-10 追加）

症状：鼠标移到弹窗的播放按钮 / 重命名按钮 / 进度条上，光标是 I-beam 竖线而不是手型，
且异常区域的垂直范围**恰好等于 `generatingContent` 的高度**。

根因（两个叠加因素）：
1. **下层 NSTextView 的 I-beam cursor rect 穿透**。
   工作台 `textEditorCard` 用的是 `EmotionTokenEditor`，内部是真实的 `NSTextView`，
   它会向所属窗口注册 I-beam 的 cursor rect。弹窗改成整窗 `.overlay` 承载后与它共处同一个 NSWindow，
   而 SwiftUI 自绘的遮罩/卡片**不是 NSView**，不参与 AppKit 的 cursor rect 判定，
   于是鼠标移到卡片上时下层的 I-beam 会穿透上来 —— 异常范围正好是卡片盖住的那块，
   高度也就恰好等于 `generatingContent`。
2. **`push()/pop()` 光标栈会被污染**。
   `pointingHandCursor()` 原先用 `NSCursor.push()/pop()`，要求 enter/exit 严格配对；
   一旦在悬浮状态下视图被移除（弹窗关闭、分支切换），exit 不触发，残留的手型会一直压在栈上。

修复：
- `DesignSystem/View+Extension.swift` 新增 `// MARK: - 光标区域屏蔽`：
  `WindowCursorRectsGuard: NSViewRepresentable`，内部 `GuardView: NSView` 重写 `viewDidMoveToWindow()`
  拿到宿主窗口（比延时猜时机准），按 `disabled` 幂等切换 `NSWindow.disableCursorRects()` /
  `enableCursorRects()` + `resetCursorRects()`；Coordinator 里用 `applied` 保证 disable/enable 严格配对。
  对外暴露 `View.suppressesCursorRects(_ active: Bool)`（用 `.background { }` 挂一个 1×1 透明占位视图）。
- `pointingHandCursor()` 改用 `NSCursor.set()`（进入 pointingHand、离开 arrow），不再依赖配对。
- `VoiceStudioView`：在 `studioContent` 上加
  `.allowsHitTesting(!showGenerationModal)`（顺带修掉弹窗显示时下层文本域仍可点击/输入的穿透）
  与 `.suppressesCursorRects(showGenerationModal)`。
- `AudioGenerationModal`：加 `import AppKit`，根节点加 `.onAppear { NSCursor.arrow.set() }` 兜底
  —— 鼠标从工作台文本域直接移上来时，先把残留的 I-beam 复位成箭头。

**经验（macOS 光标穿透）**：
- SwiftUI overlay 内容不是 NSView，挡不住下层 `NSTextView` 注册的 I-beam cursor rect。
  整窗覆盖的弹窗必须在覆盖期间 `NSWindow.disableCursorRects()`，关闭时 `enableCursorRects()` + `resetCursorRects()`。
- 不要用 `NSCursor.push()/pop()` 做 hover 光标，视图在悬浮态被移除会导致栈失衡，改用 `set()`。
