## iOS StudioParamSheet 四项音频参数持久化 + 重置按钮

需求：iOS 创作参数 Sheet 里的语速 / 音量 / 格式 / 采样率要跨重启记住，并加一个「重置」恢复默认。

### 实现
- 新增 `StudioParamStore`（`@MainActor final class`，**定义在已有的 `View/iOS/Views/Studio/StudioParamSheet.swift` 文件内**，不新建 .swift，避免改 pbxproj 四处）。
  - 独立 UserDefaults 键：`iosStudioParam.rate` / `.volume` / `.format` / `.sampleRate`。
  - `restoreIfNeeded(to:)`：进程内只跑一次（`didRestore` 守卫），四项全部校验 —— rate clamp 0.5...2.0、volume 0...100、format 只允许 mp3/wav、sampleRate 必须命中 `Constants.sampleRates`；缺键/坏值回落出厂默认。用 `object(forKey:) != nil` 判「是否存过」，不能直接用 `double(forKey:)`（缺键返回 0 会误判成用户存了音量 0）。
  - `save(from:)` 四项一起写；`reset(on:)` 回默认并立刻落盘。
  - 出厂默认：`rate 1.0 / volume 100 / format Constants.defaultFormat.lowercased() / sampleRate Constants.defaultSampleRate`。
- `StudioView.swift`：`onAppear` 调 `restoreIfNeeded`；额外挂 4 个 `.onChange` 实时落盘（挂常驻的 StudioView 而非只开一会儿的 Sheet）。`paramsText`/`sampleRateText` 本就读了这 4 个属性，不新增订阅成本。
- `StudioParamSheet.swift`：`GroupTitle(text:"音频控制")` 换成自绘的 `audioControlHeader`（样式逐项复刻 GroupTitle），右侧「重置」按钮（`arrow.counterclockwise` + 已有 key「重置」）。不放 `SheetNavBar`：leading/trailing 宽度不等会把标题挤偏。
- 三语 strings 各加 1 个新 key `"恢复语速、音量、格式与采样率的默认参数"`（accessibilityHint 用）：zh-Hans 原样 / zh-HK「復原語速、音量、格式與取樣率的預設參數」/ en "Reset speed, volume, format, and sample rate to their defaults"。术语沿用既有译法（采样率→取樣率、默认→預設、恢复→復原）。`plutil -lint` 三份均 OK。

### 关键决策 / 踩坑
- ⚠️ **刻意不复用 `AppState.defaultFormat` / `defaultSampleRate`**：那两项是 macOS「设置页默认值」语义（iOS 设置页照搬同一组 UserDefaults 键），工作台调参数不该改写用户的全局默认设置。两套状态独立，`View/iOS/` 下的 Store 不进 macOS target，macOS 零影响。
- ⚠️ iOS 工作台**本来就不读** AppState 的两项默认值（macOS `VoiceStudioView.onAppear` 才读），本次没去接这条联动，保持既有行为。
- 重置只覆盖这 4 项；音色、语音指令、语言 / 预设不动。默认值取出厂常量而非设置页配置 —— 若以后要改成「跟随设置页默认」，把 `reset` 里 format/sampleRate 换成读 AppState 即可。
- `didRestore` 是进程内标志：切 tab 回来 `onAppear` 会再跑，不能被磁盘旧值盖掉本次会话的实时值。

## 09:57 「设置音频格式，默认 mp3」——把剩余写死的默认兜底统一到常量

用户选择的范围是**统一代码默认值**（不做旧存档强制迁移、不动 macOS 设置页的 PCM/Opus 选项），即：新装 / 从未设置过的设备默认 MP3，已经存过 WAV 的设备保留用户自己的选择。

### ⚠️ 关键坑：默认参数求值是非隔离上下文
第一次构建虽 `BUILD SUCCEEDED`，但 grep 日志发现**新增 2 条** `main actor-isolated static property 'defaultFormat'/'defaultSampleRate' can not be referenced from a nonisolated context`（只报在 `synthesize` 的 line 62/63）。根因还是工程默认 `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`：`Constants` 的 static let 被判 @MainActor，而默认实参在调用方的非隔离上下文求值。Swift 5 模式下只是 warning、不挂 exit code，**必须 grep 日志才发现**。修法是给这两个 Sendable 纯值常量加 `nonisolated`（放宽隔离，其它 MainActor 调用点不受影响）。以后任何非隔离服务/后台代码要读 `Constants` 的静态常量，都得先确认该常量是否 `nonisolated`。

## 10:51 macOS 点「重置」格式回到 WAV —— 修复

用户实测：macOS 工作台点「重置」后格式是 WAV 而非 MP3（iOS 正常）。

### 根因
上一轮我把 macOS 重置写成 `reset(on: vm, to: studioParamDefaults)`，而 `studioParamDefaults.format = appState.defaultFormat`（设置页默认值）。只要该值是 `WAV`（旧版默认残留 / 用户在设置页选过），`StudioParamStore.sanitize` 的白名单 `["mp3","wav"]` 会**原样保留** `wav` —— 于是重置回到 WAV。iOS 走 `reset(on: vm)`（`.factory` 出厂值），所以只有 macOS 中招。本机 `~/Library/Containers/com.emotion.voice` 下没查到 plist（`defaults read com.emotion.voice` 报 domain not found），推测是运行中的 cfprefsd 缓存 / 旧构建内存值，但无论来源如何，重置都不该依赖它。

### 修复（2 个文件）
- `View/macOS/VoiceStudioView/VoiceStudioView.swift`：`reset(on: vm, to: studioParamDefaults)` → `reset(on: vm)`；三处注释改口径（onAppear / `studioParamDefaults` 文档 / 按钮）。`restoreIfNeeded(to:defaults:)` **保持不变** —— 设置页的值仍作「无存档起点」。
- `Shared/ViewModels/VoiceStudioViewModel.swift`：更新 Store 顶部与 `reset` 的文档注释，写明「重置一律回 `.factory`，调用方一般不要传 defaults」。

新的语义分工：**设置页默认值 → 只管首次启动无存档起点；重置 → 一律出厂 mp3**。两端重置行为完全一致。

## iOS 音色库：切标签后「分类=全部但列表空」修复
**根因（不是筛选、不是数据源）**：`VoicesLibraryView.apply(_:_:)` 把**数据落地**和淡入动画绑在同一个 `swapTask` 里，闭包开头 `guard !Task.isCancelled else { return }`；而 `.onDisappear` 无条件 `swapTask?.cancel()`。取消 = 这批数据被丢弃，于是 `voices=[]`、`didLoad=true`。
- `.task { initialLoad() }` 只在视图首次出现跑一次且开头 `guard !didLoad else { return }` → 切回标签不会重跑；`VoiceLibraryFilterStore` 初始值仍是 nil/""/false，所以按钮显示「全部分类」但列表永久空。
- TabView 三个 tab 同在 body 里构造，iOS 会预挂载非激活 tab，`.task` 可能在 app 启动时（用户还在创作页）就跑，`onDisappear` 紧随其后 → **首次点进音色库就已经是空态**，与用户描述吻合。
- 已排除：`ScreenMetrics.voiceGridColumns` 恒 ≥2（不会 0 列）；`VoiceService` 数据在 AppState init 前由 `DatabaseManager.syncVoicesIfNeeded()` 同步；`vm.reloadCurrentPage()` 首次 `lastQueryKey=""` 必重算，`isLoading` 虽一直是 true 但 iOS 视图不依赖它、每次 `reload()` 都显式查库。

**修法（`View/iOS/Views/Library/VoicesLibraryView.swift` + `View/iOS/Views/Studio/VoicePickerSheet.swift`，后者是同逻辑复制）**：
- 抽出 `commit(_:_:)`（voices / totalCount / scrollResetID），正常淡入、被取消、`animated:false` 三条路径全部走它；取消分支只`contentVisible = true`，**不再 return 丢数据**。
- `VoicesLibraryView` 加 `@State didAppearOnce` + `.onAppear` 自愈：`didAppearOnce && didLoad && voices.isEmpty && vm.totalCount > 0` → `reload(animated:false)`。用 `vm.totalCount`（同步查库、不受 swapTask 影响）区分「没落地」与「搜索确实无结果」；`didAppearOnce` 保证首次出现不吃掉骨架淡入。
- `onDisappear` 原有 `pendingSheetReload` 分支的 `reload(animated:false)` 保留，现在也走 `commit`。

1. ⚠️ **`editorMinHeight` 的 `min(height-190, 520)` 上限**：iPad 竖屏被硬夹到 520pt，而可用高约 1000pt。这个 520 是当初为「折叠屏展开态横屏 951×669」调的，误伤了真正的大屏。
2. ⚠️ **双重水平边距**：`wideLayout.pagePadding()` 加 24pt，内部 `textCard` / `voiceRow` / `paramsSummary` 又各加 `metrics.pageMargin`(24) → 左右各 48pt，编辑卡被压到 ~410pt、侧栏卡片只剩 252pt。
3. ⚠️ **iPadOS 18 的 TabView 把标签栏放到顶部**（截图中间 Create/Voice Library/Project 胶囊，两侧 logo / 积分 / 设置），底部**没有** tabBar；`RootTabView` 三条浮层硬写 `padding(.bottom, 58)` → mini player / 后台浮条 / Toast 会悬空。iPhone 截图实测底部是浮动 tabBar（58 正确），两端不能共用一个常数。

### 改动（3 文件，零 pbxproj / 零新增 .swift）
- `Layout/ScreenMetrics.swift`
  - 新增 `isPadClass = width >= 740 && height >= 700`（**700 卡在 Duo 展开态横屏 669 与 iPad mini 横屏 744 之间**；不能用 `sizeClass == .regular`，iPad 分屏 410×1180 也是 regular 但必须单列）。

  - `editorMinHeight` 去掉 520 cap，改 `max(260, height-190)`，退居兜底。

- `Views/Studio/StudioView.swift`
  - 宽屏分支外套 **`GeometryReader` 实测「generateBar 之上」的高度**，`wideLayout(editorHeight: max(geo.height-20, editorMinHeight))` 直接给编辑卡 `.frame(height:)`；ScrollView 保留（滑动收键盘不丢），内容刚好一屏不产生滚动。
  - `wideLayout` 改成函数、**去掉 `.pagePadding()`**，只在 HStack 外层加一次 `.padding(.horizontal, pageMargin)`；`textCard(horizontalInset:)` 参数化（窄屏传 `pageMargin`、两栏传 0），`voiceRow`/`paramsSummary` 删掉内层水平 padding。
  - `paramsSummary` 的 Text 加 `.minimumScaleFactor(0.8)`，修 iPad 上 `22.05 kHz` 被截成 `22.05 k…`。
- `App/RootTabView.swift`：`ScreenMetricsReader { _ in }` → `{ metrics in }`；`bottomDock` 改 `func bottomDock(tabBarClearance:)`，三处 58 换成实参；更新横幅的 `navBarClearance` 在 iPad 上 +8pt。

## 15:04 iPad 创作页：参数摘要条 → 侧栏直接铺开完整参数面板

  - `StudioParamSheet`：只剩 `SheetNavBar` + `VStack` 外壳，正文换成 `StudioParamContent(vm:voicePickerPresented:)`。iPhone 的 Sheet 层级 / 间距 / 控件行为与拆分前逐字一致。
