## 修复：句卡只有 1 句（分句判据看错了标点位置）
- **现象**：273 字音频阅读区只有「273 字 · 1 句」，点哪都从头播。
- **根因**：上一版 `splitBySentenceEnding` 判据是 `word.text.last` 是否句末标点。实测上游把标点粘在**后一个字的前面**：`想`/`啥`/`呢`/`。"星`/`河`，所以 `word.text.last` 永远是汉字，除整段最后一个 word 外永不成立 → 只切出 1 句。
- **修法**：改为扫 word 的**前导标点簇**（`chars[p].isPunctuation`），切点落在簇内部；用 `inQuote` 状态机区分闭引号（`。"星` → 引号归前句）与开引号（`。"哥` → 引号留给后句）。只改 `text`，`beginMs/endMs` 一个不动（零估算）。

- **sidecar 迁移**：`AudioTimeline.currentVersion = 2`，`AudioTimelineStore.load` 检测到低版本就拍平 words 重切并回写，**用户不用重新生成音频**。⚠️ v2 产物不可再跑 v2 切分（标点已前移，重切会退化成一整段），已写进注释与 MEMORY。

- 现象：英文生成的播放界面 6 张句卡全是 `Today,AIIspoweredbydeeplearning,…`，单词之间没有任何空格（中文没问题，所以一直没暴露）。
- 根因：`TTSTimestampParser.remap` 把原文先 `filter { !$0.isWhitespace }` 化成纯字符数组再按字数回填，等于把所有空格从字幕里删掉。中文靠标点断句无感，英文靠空格断词就全粘了。
- 修法：新增 `normalizeWhitespace()`（连续空白压成一个空格、去首尾），`remap` 改为按「非空白字符计数」对齐、但切片从归一后的原文取（`visible: [Int]` 把去空白序号换算回真实下标），两条通道都保留词间空白；校验也改成「去空白后逐字相等」。
- 顺手修相邻缺陷：`splitBySentenceEnding` 原来只认 word 的**前导**标点簇，西文标点在词尾（`brain.`）时 `cut` 恒为 -1 → 整段只切 1 张卡。新增 `endsWithTerminal()`（跳过尾部空白/引号）单独断一次；同时前导扫标点时先跳过空白（词可能带前导空格）。句首词的残余前导空格在 `flush()` 里削掉，避免卡片多出一截缩进。
- 版本：`AudioTimeline.currentVersion` 3 → 4。v3→v4 走 `realign`（序号通道）；英文 v3 sidecar 序号对不上时，`lostWordSpacing()`（拼接无空白 + 原文有拉丁字母间空格）允许退回逐位通道补回空格。
- 验证：typecheck 0 error；`ios_build.sh mac` BUILD SUCCEEDED；Python 复刻四场景通过 —— 英文标点词尾 2 句且空格完整、中文标点前置/词尾都 2 句、引号场景仍切对（`我说："想啥呢。"` / `星河在动。`）。
- 未验证：实机容器受 TCC 限制读不到 sidecar，旧英文音频的 v3→v4 迁移需打开旧音频实测。

## 对照阿里云时间戳文档复核 + v5（切句规则版本化）
- 文档核对结论：用户给的《时间戳功能介绍》讲的是**长文本合成 MetaInfo/subtitles** 协议，文字描述「`begin_index` 是该字在**整句**中的开始位置」**是错的**，它自己的示例就矛盾 —— `阿里巴巴。达摩院。` 里「达」是 index 4（不是句内 0）。真相：**占号单元的全文连续序号**（标点不占号、跨句累加），与我们实测一致。所以官方建议的「`sentence_offset` + `begin_index`」在本协议里等价于直接用 `begin_index`；真去累加句长反而多一层「上游回传句长 = 原文该句长度」的假设。用户已确认这条判读。
- 「用原文上屏、`text` 不可上屏」这一条文档说得对，v3 起已经这么做（`alignToOriginal` 落盘前重写 word 文本，渲染只拼 `word.text`）。
- **修掉的真 bug 1：v4 历史数据永远不会自愈**。`load` 里 `version >= currentVersion && textMatches` 直接返回不重切 → 上一轮补的 `endsWithTerminal`（西文词尾断句）对已落盘的 v4 英文 sidecar 完全无效，「整段 1 张卡」永远不修。修法：`currentVersion` 4 → 5，**版本低于当前一律 `realign`（重排 + 重切），不看 `textMatches`**；无原文走 `regrade` 只重切。
- **修掉的真 bug 2：v4 英文数据在 realign 里被「兜底条件」挡住**。原来 `if realigned == nil, contaminated, lostWordSpacing(...)` 才允许退回逐位通道；v4 英文文本已有空格 → `lostWordSpacing` 为 false → 直接放弃。改为**无条件**退回逐位通道（两条通道都以「去空白后逐字相等」收尾，最坏只是词边界偏一个字符），`lostWordSpacing` 删除。
- **修掉的真 bug 3：占号口径**。`!chars[i].isPunctuation` 把 `isSymbol` 的 `%` `$` `~` `=` 当成占号单元，原文出现百分号/货币符号时整条对齐判失败、静默退回上游文本。新增 `isSpokenUnit()`（只认字母/数字），与「不发音的字符不占号」对齐。
- **加固 1：序号通道放宽**。段内原来要求「逐词首尾严格相接」（`begin == prev.end`），上游给空 text 占位词（解析时已丢弃）或跳号就整条降级。改为**单调不减**，空洞字符并入下一个词词首；真正防错位靠末尾 `unitOffset == unitVisible.count` 总量校验。
- **加固 2：纯标点词**。`begin_index == end_index`（独立 `。`）会让切片得到空串、`joined` 校验不过。新增分支：纯标点词吃「到下一个占号单元之前」的字符。同时段边界判定加 `endIndex > 0`，避免 `。` 被误判成新段起点。
- **加固 3**：`splitBySentenceEnding` 拼 tail 时从 `punctStart` 起取（原来从 `chars[0]`），不再把前导空白拼进上一句末尾。`alignToOriginal` 的次选 `original_text` 只在 `cues.count == 1` 时使用（多句时那个 text 只是本句，必然失败）。`BailianTTSService` 的对齐日志改成「成功 / 失败（字数对不上或被读法展开）」，直接能判对齐结果。
- 验证：`tools/ios_typecheck/typecheck.sh` 0 error；`tools/ios_build.sh mac` BUILD SUCCEEDED；`/tmp/ts_verify.py`（Python 复刻 v5 算法）11 项全过 —— 繁体还原、英文 2 句卡、v4 污染数据兜底重切、序号空洞合并、纯标点词、`[break]` 多段、符号不占号。
- 未验证：实机 sidecar 受 TCC 拦截，v4 → v5 重切需打开旧英文音频实测（预期句卡从 1 张变成多张）。

## 繁中长文仍显示简体 —— 新增通道 ②（v6）
- 现象：1251 字繁中长文（含 `「」`、段间空行、英文括注 `（Default Mode Network）`）生成后字幕全是简体。上一轮 v5 的修复没覆盖到。
- 根因（用日志里的 `original_text` / `normalized_text` 实测）：上游 normalize 做了两件**都不占号**但会让两条通道同时失效的事 ——
  1. 删掉 4 个 `「」`、把 3 处段间 `\n\n` 换成 `。`（+1）→ 非空白字符数 **353 → 350**，逐位通道「字数相等」前提不成立；
  2. 英文 `Default Mode Network` 的 `begin_index` 按**词**编号（3 个），我们按**字母**数占号单元（18 个）→ 上游 index 总量对不上，通道 ③ 的总量校验必然失败。
  而两边的**占号单元数都是 319**（`謐`→`密`、`癒`→`愈`、`睜`→`争`、`螢`→`营` 全是 1 换 1）。
- 修法：`remap` 从「① 逐位 + ② 上游 index」扩成**三条通道**，在两者之间插入通道 ② —— 只数 `word.text` 里有多少个占号字符，累加后把原文按占号单元一段段切给 words（`countedUnitEnds` + `sliceByUnitEnds`）。完全不看上游 index、也不要求字数相等，标点增删与字形归一化都无影响。上游 index 通道降级为 ③ 兜底（`upstreamUnitEnds`，含 `[break]` 分段归零累加）。
- 顺手把两条通道的切片逻辑合并成 `sliceByUnitEnds`：纯标点词（`begin==end` / 计数为 0）吃「到下一个占号单元之前」的字符、段内单调不减（空洞字符并入下一个词词首）、末尾残留标点补到最后一个词 —— 三处处理只写一遍，不再两份分叉。
- 版本：`AudioTimeline.currentVersion` 5 → 6。**对齐算法（通道数量/优先级）也属于要 bump 的范畴** —— 只靠 `textMatches` 拦不住，它只能发现「文本不等」，发现不了「文本对但用了旧算法」。
- 验证：`typecheck` 0 error、`ios_build.sh mac` BUILD SUCCEEDED；`/tmp/ts_real.py` 用日志里那条长文的真实 `original_text` + `normalized_text` 复刻（英文按字母 / 按词两种构造）均 `通道=②` 且整段还原成繁体；`/tmp/ts_verify2.py` 旧 11 场景全过（C 场景现在走 ②，词边界变化但文本正确）。
- 未验证：实机仍是 TCC 拦截，需用户重新生成或打开旧音频实测（旧 sidecar 是 v5，会被 `version < current` 触发 realign 自愈）。
