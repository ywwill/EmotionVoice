## 生成弹窗：数据块日志 → DataReceiveGridView（真实接收可视化）
- `AudioGenerationModal` 原「数据块到达日志」（4 行文字 + 200ms 合并节流）替换为 `DataReceiveGridView`：
  WebSocket 每来一批数据点亮若干格，自下而上堆叠、列满换右边一列；下方新增 `GridCaptionView`
  （唯一订阅网格数据源的小视图，避免 10Hz/60Hz 把整个弹窗带着重算）。删除 `ChunkLine` / `chunkLog`
  / `lastLogDate` / `appendChunkLog`。
- **一格代表多少字节是算出来的**（`prepareGrid()`，在 `onAppear` 与「新一轮生成把统计清零」时调用）：
  字数 → 时长（沿用 VM 的 "每秒 12 字、最少 2.5s" 口径）→ 字节数（WAV = sampleRate×2，有损 16KB/s，
  与 `AudioDuration.estimate` 同口径）→ ÷ 目标格数 110 = bytesPerCell（下限 512B）。
  短句不会只亮几个格、长篇也不会糊成一片。`feedGrid(bytes:)` 有余量累加 + 至少 1 格 + 单批最多 12 格。
- 注意 `stats` 本身 10Hz 节流发布，所以"每一次接收到数据"= 一次发布批次，不是未节流的每一帧。
- 参数：rows=4、cellSize=11、spacing=4、cornerRadius=3.2；可用宽 498 → 33 列（列间距微调到 4.22）。

## 修复：网格左右边缘出现残缺方块
- 根因两条：① 列数按 `ceil(宽度/步进)` 再乘回步进，画布往往比可视宽多出一截，最右一列被容器切掉；
  ② 自动跟随的锚点 View 宽 1pt，内容永远比可视区宽 1pt，跟随时会把整块内容往左拽 1pt，左边第一格被切。
- 改法：`Layout` 把列步进与行步进拆开；列数取 `floor((可用宽+期望间距)/(格宽+期望间距))`（保证真实列间距 ≥
  期望值），列间距 = (可用宽 − n×格宽)/(n−1)，首列贴左、末列贴右；超宽时画布 = n×列步进 − 列间距。
  锚点改成 **零宽**（`.frame(width: 0)`）。
- 验证：`swiftc -typecheck -disable-sandbox -swift-version 5 -target arm64-apple-macos14.0
  -I <DerivedData>/Build/Products/Debug` 全项目零新增 error（仅 StoreKitManager 因本次排除了
  CreditsService.swift 而报 cannot find CreditsService）。

## 修复：边缘格子点亮时白环缺一角
- 高亮环画在格子外面（`insetBy(-1)` + 线宽 1.2 → 实际外扩约 1.6pt），而顶行 / 最右一列的格子本来
  就贴着画布边界 → 最新一格落在那里时，环的上边或右边被画布裁掉。
- 解法：给画布四周预留 `haloOutset = 2`。`Layout` 新增 `outset` 字段（`cellRect` 统一加偏移）与
  `canvasHeight = gridHeight + 2×outset`；排列宽度改成 `可视宽 − 2×outset`（列数重算，仍保证列间距 ≥ 期望值）；
  超宽时的画布宽也补上 2×outset。环的外扩常量抽成 `haloRingInset`。
- 实测（弹窗 498 可用宽）：仍 33 列，列间距 4.09，最右格右边 + 环 1.6 距边界还剩 0.4pt。

## 修复：生成弹窗「接收中 → 完成」切换时卡顿一下
- 主因是**同一帧被切成了两次 SwiftUI 更新**：完成态原由本地 `@State isCompleted` 判定，而它只能在
  `onChange(of: stats.progress)` 里翻 —— onChange 跑在 body 求值**之后**，于是先渲染一帧
  「已完成内容 + 未完成装饰」的半成品，下一个事务再 `withAnimation` 跳一次，观感就是"顿一下"。
- 改法：删掉 `isCompleted` / `audioDuration` / `finishedElapsed` / `finishedChunkCount` 四个 @State，
  新增 `hasResult = vm.generatedAudioURL != nil && !vm.isGenerating`（直接读 VM 的 @Published ——
  URL、时长、`isGenerating=false` 是 `MainActor.run` 里连续赋值的，会合并进同一次 view 更新）；
  `isGenerating = vm.isGenerating && !hasResult`。header/遮罩点击据此渲染，播放器与时长直接读 VM。
  ⚠️ 铁律：这类「状态切换」不要走「本地 Bool + onChange」的中转。
- 动画从两条（`.animation(value: isGenerating)` + `value: isCompleted`）合并成一条 0.22s（原 0.35s）。
- `refreshCompletedInfo()` 的磁盘 I/O 挪到 `DispatchQueue.global(.utility)`，先用 `stats.receivedBytes`
  的格式化结果兜底（界面不闪 "—"），回填前校验 `vm.generatedAudioURL` 未变（防止新一轮串档）。
- `DataReceiveGridView`：① `onPreferenceChange(TailFrameKey)` 里无条件写 `followTail` 会在任何布局动画
  期间逐帧触发整个 body（GeometryReader+Canvas+ScrollView）重算 —— 改成「值翻转才写」；
  ② 底槽从逐格 `context.fill`（165 次）改成攒一条 `Path` 一次 fill。
- 验证：`swiftc -typecheck` 零新增 error（仍只剩 StoreKitManager 那条与本次无关的报错）。
