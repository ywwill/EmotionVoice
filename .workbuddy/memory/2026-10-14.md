## 修复：删除标签后原位置遗留两三个空格
- 根因：每个 token 在 `insertToken` 插入时会自动补一个 prefix 分隔空格；删除只删掉 1 字符的 attachment，留下该空格，相邻 token 的 prefix 空格叠加成双/三空格。
- 新增共享函数 `emotionTokenDeletionRange(_:in:)`（EmotionTokenStyle.swift）：仅当 token「前、后都紧邻空白（或位于文末）」才额外吞掉前面的空格——既折叠相邻 token 的双/三空格，又不会把前后文字黏在一起（后非空白时保留空格作分隔）。
- 新增 `EmotionTokenTextView.removeToken(at:)` 统一入口（含 shouldChangeText/didChangeText/选区重置）；`deleteBackward`/`deleteForward` 的全部 token 分支与 cell 的 × 点击（`trackMouse`，改 cast 为 EmotionTokenTextView）都改走它；`clearAllTokens` 也按扩展范围删除避免空格串。
- `swiftc -parse` 三个文件通过。

## 修复：标签 × 删除图标静止态看不见（仅悬停才显）
- 反馈：插入的标签删除图标"只有鼠标移上去才显示"。根因：静止态透明度 0.35，在中性胶囊上几乎不可见。
- `EmotionTokenAttachmentCell.swift` 绘制 × 处：静止态 alpha 0.35 → 0.55（清晰可见），悬停/选中仍提亮为满色。`swiftc -parse` 通过。

## 改动：插入标签时不再自动补前缀空格
- 用户要求：插入标签不要再在前面自动加空格。
- `EmotionTokenTextView.insertToken`：删掉 prefix 空格逻辑，直接在光标处插入 token attachment（是否留间隔交由用户在普通文本里自行敲）。
- 配套简化：`emotionTokenDeletionRange(_:in:)`（EmotionTokenStyle.swift）整个删除——它原本只用来收掉"自动补的 prefix 空格"。`removeToken(at:)`、`clearAllTokens` 改为直接删 token range，不再做前缀空格扩展（用户手动敲的空格应保留）。
