## v4：下划线加粗+留间距 & 修「插入标签后输入卡顿」
### 1. 下划线改为自绘（EmotionTokenTextView / EmotionTokenStyle）
- AppKit 的 `.underlineStyle` 无法控制粗细与「离正文的间距」→ 改为 `override draw(_:)` 里
  `super.draw(rect)` 之后自己画：`toneScopes: [ToneScope]`（字符区间 + 解析好颜色）只作绘图数据。
- 逐行几何（`enumerateLineFragments`）：
  `baseline = lineFragmentRect.minY + lm.location(forGlyphAt:).y`（头文件明言 glyph location 相对
  line fragment 原点，实测 baseline=14.0 与 `usedRect.maxY + descender`=14.05 吻合）；
  下划线 y = `baseline - font.descender + underlineGap`，圆角 = 半厚。
- 样式：underlineThickness 2→2.5，新增 underlineGap=2，新增 `EmotionTokenStyle.bodyFont/bodyFontSize`。
### 2. 「下方标注」下移避让下划线（关键连带改动）
- 附件基线约定（实测）：**cellFrame.maxY = baseline - cellBaselineOffset.y**（负 offset = cell 低于基线）。
  据此：标注顶端 = `baseline + |descender| + annotationGap`。
- 下划线底部到基线 +7.45，原 annotationGap=3（标注顶端 基线+5.95）会与下划线重叠 → annotationGap 3→7
  （标注顶端 基线+9.95，净空 2.5pt）。离屏实测：下划线 19.95…22.45，标注顶端 25.0，净空 2.55 ✓。
### 3. 输入卡顿的根因与修复
- 根因 A（主因）：旧 `applyToneScopes()` 每次按键都 `beginEditing → 全文档 removeAttribute/addAttribute
  → endEditing`，endEditing 触发全文档 processEditing（属性修正+布局失效+重排）。
  → 现在完全不写 NSTextStorage，只 O(n) 枚举附件算区间，零重排。
- 根因 B：每次按键 `onContentChange` → VM @Published 写入 → 整个 VoiceStudioView 重算 body，
  且 `updateNSView` 每次都全量 `exportItems()` 比对。
  → ① `didChangeText` 后去抖 0.35s（`DispatchWorkItem` 取消重试），输入停下才归纳到 items；
    插入/删除/粘贴/setContent/失焦 走 `flushPendingContentChange()` 立即同步；
    ② Coordinator 加 `lastExportedFromView` 缓存，binding 未变时跳过 exportItems 全量扫描。
- 另加 `viewDidChangeEffectiveAppearance()` 时重算 scopes（颜色缓存了 dark 判定）。
- 校验：swiftc -typecheck 全绿；另写两个离屏小程序（/tmp）验证基线/附件基线/下划线-标注净空。
- 设计稿 `UI/emotion_token_editor_underline_v3.html` 同步：border-bottom 2→2.5px、padding-bottom 2→3px、
  标注 margin-top 1→5px。

## v6：修「拟声标签的 × 鼠标移过去就消失、无法删除」
### 根因（离屏实测定位）
1. hover 判定只用了**字形矩形**，而 × 圆钮画在胶囊**上沿之外**（circle 中心 = (maxX-d/2, minY-d/2)）。
   实测拟声 cell frame = (112.1, 0, 44, 22)，× 命中区 = (137.1, **-19**, 22, 22) —— 整个圆都在
   字形矩形之外。鼠标一动，hover 立刻丢 → × 消失（且 `hitTestTokenDelete` 有 hovered 门槛 → 点不掉）。
2. 顺带查出 `lm.boundingRect(forGlyphRange:in:)` 的**高度会被抬高到行高**（拟声 cell 实际 22，

## v7：鼠标在标签上移动时「小手 ↔ 箭头」来回闪
- 成因：在 `mouseMoved` 里调 `NSCursor.set()` 只是**临时**设置；`NSTextView` 自己注册了 I-beam 的
  cursor rect（见 `DesignSystem/View+Extension.swift` 里 WindowCursorRectsGuard 的注释也提到这一点），
  窗口的 cursor-rect 机制随后会把游标改回去 → 下一次 mouseMoved 又抢回小手 → 反复抖动。
  而且 AppKit 每收到一次 set 都可能触发一轮 cursor 更新，重复 set 本身就是抖动的放大器。
- 修复（EmotionTokenTextView）：
  - 追踪区 options 加 `.cursorUpdate`：`[.mouseMoved, .cursorUpdate, .activeInActiveApp, .inVisibleRect]`。
  - 新增 `override cursorUpdate(with:)`：先 `super` 再 set —— **这是 AppKit 正规的游标钩子**，
    窗口需要重新确认游标时就在这里回答，才不会被系统改回去。
  - 抽出 `desiredCursor(at:)`：mouseMoved 与 cursorUpdate 共用同一判断，口径不会打架。
  - 加去重 `appliedCursor`（`NSCursor.pointingHand` / `.iBeam` 是**单例**，实测 `===` 比较成立），
    样式没变就不重复 set。
  - `mouseExited` 里同步 `appliedCursor = .iBeam` 保持一致。
- 沙箱无 Window Server，**游标行为无法离屏验证**，需用户在 Xcode 实跑确认。

## 倍速显示：选中 1.25x 却显示成 1.2x
- 根因：`Views/HistoryView/PlayerTextMetrics.formatRate` 用了 `String(format: "%.2g×", rate)`。
  `%.2g` 是「保留 **2 位有效数字**」，1.25 → "1.2"；而且它拼的是 `×`(U+00D7)，
  与菜单 `playbackRateOptions` 的 `x`(ASCII) 也不一致。
