## 修订：窗口首屏铺满（占满可视区域）
- 用户把 ContentView 下限改为 `.frame(minWidth:1000, minHeight:800)`，并要求每次打开 app 窗口占满屏幕。
- 重做 `WindowAccessor`：重新挂 `.background(WindowAccessor())`；`designMinSize = 1000×800`；
  首屏用 `window.setFrame(visibleFrame, display:, animate:false)` 铺满「可视区域」（排除菜单栏+Dock），
  极小屏（可视 < 最小）退化为居中放最小尺寸窗口；`minSize.height` 下限钳到 640 防撑爆；
  保留透明标题栏 + 背景 0x0E0F12 的原设计观感。
- 残留风险：极小屏（可视高度 < 800）下 ContentView 的 minHeight 800 可能略大于窗口 → 轻微裁切；
  以及右栏 editPanel 的 ScrollView 无 maxHeight 约束、在正好 800 高度时可能贴边。正常屏幕铺满后不触发。
  如需彻底保险，可再把 editPanel 限制 `maxHeight:.infinity` 让其内部滚动（用户此前中断了该项改动，暂未做）。

## AudioGenerationModal：未播放时点击波形可调整进度
- 需求：接收数据结束后（还没播放），点击频谱要能定位进度/播放头，而不是弹回 0。
- 根因：`AudioPreviewPlayer.seek()` 只在已有 player/avPlayer 实例时生效；未播放过 → `playingKey==nil`、`player==nil`，点击只调了 `seek`（空操作），松手后 `isScrubbing=false` 使 `displayProgress` 回退到 `player.progress(=0)`，播放头弹回。
- 改 `ModalAudioPlayer`：新增 `@State manualProgress: Double`；
  - 新增 `hasLoadedPlayer`（playingKey==url.path 且 isPlaying||isPaused）作为「progress 是否可信」判别；
  - `displayProgress/displayTime`：拖动时取 scrubProgress，已加载取 player，未加载取 manualProgress；
  - 波形 `DragGesture.onChanged`：已加载 → 实时 `seek`，未加载 → 记 `manualProgress`（播放头/时间随之移动并稳住）；
  - `togglePlayback` 点播放后若 `manualProgress>0` 先 `seek` 到该位置再放（实现"点哪从哪播"）。
- 注意：`ModalAudioPlayer` 由 `completedContent` 的 `if let url` 包裹，URL 变更会重建实例 → manualProgress 自然归零；弹窗消失时 `onDisappear` 调 `AudioPreviewPlayer.shared.stop()`（清 playingKey/player）也契合未加载态。

## AudioGenerationModal 两个 bug 修复
- Bug1「暂停后播放头跳回点击位置 a」：根因 `ModalAudioPlayer.togglePlayback()` 的"暂停"分支误调 `player.stop()`（而非 `pause()`）。stop() 清掉 player/progress 并把 playingKey 置 nil → 后续 `displayProgress` 回退到 `manualProgress`（上次点波形的位置 a），而非真实暂停点 b。改法：该分支改为 `player.pause()` 真暂停（保留 player + 进度），`hasLoadedPlayer` 在暂停态仍为真 → 播放头停在 b；再次点击走 `player.resume()` 从 b 续播。
- Bug2「点弹窗外弹窗消失」：遮罩 `Color.black.opacity(0.75)` 上挂了 `.onTapGesture { if hasResult { dismiss() } }`，点弹窗外即收起界面。改法：删掉该 onTapGesture，遮罩只做视觉压暗；关闭仅保留右上角 X 与 Esc（`.onExitCommand`）。
- 验证：Xcode 真机构建跑一遍「播放→点波形→播放到 b→暂停（应停在 b）→继续（从 b 播）」以及「点弹窗外不应关闭」。
