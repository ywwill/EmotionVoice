Design Proposal / Drafts

把「还没生成的内容」留下来

草稿保存的是编辑态的完整快照，不是一段纯文本：正文里的情绪 / 拟声 / 中断标签及其插入位置、当前音色、语速音量格式采样率、语音指令一起存。点任意一条草稿即可回到当时的编辑状态，继续写、继续调、继续生成。

就地保存，不打断心流

入口常驻「文本输入」卡片头部。macOS 走 Popover，iOS 走 Sheet，都不跳页、不打断当前输入焦点。

恢复前自动兜底

当前编辑区非空时，恢复会先把现有内容自动存为一份「自动保存」草稿，并提供 8 秒可撤销，永不出现「一点就丢」。

草稿 ≠ 项目

草稿是「未生成」的编辑态；生成成功后的音频进入「项目 / 历史」。两者数据、入口、生命周期分开，不混列。

1核心链路 两条通道共用同一份草稿仓库

01 / WRITE
编辑创作台

输入正文、插入情绪标签、选音色、调参数。系统静默维护一份「当前工作区」快照。

02 / SAVE
存为草稿

手动点「存为草稿」生成命名条目；退到后台 / 切页 / 被系统回收时自动生成一条覆盖式「自动保存」。

03 / BROWSE
草稿列表

按时间倒序，展示首行摘要、字数、音色、标签数与保存时间；支持搜索、重命名、删除。

04 / RESTORE
点一条即恢复

整条写入 VM 与编辑器（含 token 序列与参数），回到创作页顶部提示「已从草稿恢复 · 撤销」。

整条热区可点 恢复需确认（当前非空时） 8s 撤销窗口 自动保存单条覆盖 云端同步留接口，本期本机

设计取舍：不做「新建空白 / 多文档标签页」那套文档模型。本产品的创作台是单例编辑区，草稿是它的存档点而不是独立文档，避免引入项目、版本树、冲突合并这套心智负担。

2草稿快照字段 恢复时逐字段写回，缺一不可

字段内容恢复去向 / 说明
正文 + 标签富文本 token 序列（文本片段 + 情绪 / 拟声 / 中断标签及插入位置）写回 ttsItems（macOS）/ TokenDocument（iOS）。不存纯文本，否则标签位置全丢。两端共用同一份 JSON 序列化格式。
音色voiceKey + 展示名快照写回 AppState.selectedVoice 与 VM；音色下架时回落默认音色并在提示条说明。
四项参数语速 / 音量 / 格式 / 采样率写回 VoiceStudioViewModel 并同步 StudioParamStore，避免「界面变了、下次冷启动又回旧值」。
语音指令语言、预设、自定义指令文本整段回填；拼接文案必须走本地化，草稿只存语义值不存拼好的中文句子。
元信息标题（取正文首行，可重命名）、字数、标签数、保存时间、来源（手动 / 自动）列表渲染用；标题为空时显示「未命名草稿」，不显示空白行。

C落地约束 与现有工程实现对齐，避免返工

约束说明
存储不与软删混用新建独立 DraftStore（JSON / UserDefaults 或独立文件），不要塞进 AudioFlagStore（那是收藏 / 软删、30 天到期会 purge）。若要用 SQLite，注意改 createTables() 必须 bump schemaVersion 并会 DROP 重建，草稿属于用户资产，丢不起，建议不进 SQLite。
token 序列统一macOS TTSContentItem[] 与 iOS TokenDocument 结构不同，恢复前需一份与平台无关的 JSON 中间格式；两端各自做编解码，禁止把富文本降成纯文本存。
参数写回双向恢复时同时写 VoiceStudioViewModel 与 StudioParamStore；否则界面变了但冷启动 restoreIfNeeded 又拉回旧值。参数面板唯一数据源仍是 StudioParamContent。
常驻页生命周期macOS 工作台在 ContentView 里是常驻 ZStack（切页只切 opacity），草稿 Popover 必须随 isActive == false 一起收掉；恢复会重建 NSTextView 内容，需交出 firstResponder 后再写，避免光标错位。
iOS 键盘与浮层打开草稿 Sheet 前先收键盘（finishEditing()）；恢复后不自动聚焦、不弹键盘。提示条是页面内浮层，不参与 keyboardSeam 计算。
不订阅高频状态草稿入口只读 drafts.count（低频）；禁止把 AudioPreviewPlayer 的 10Hz 发布者挂到入口或列表上。

D待确认 出图按推荐方案，确认后进入实现

1

同步范围

本图按本机存储设计（文案写「本机」）。是否本期就要 iCloud / Supabase 跨设备同步？若要，列表需加同步状态、冲突策略与账户入口，是另一套设计。

2

自动保存策略

本图采用「单条覆盖式自动保存」。是否要保留最近 N 次历史快照？会引入版本列表与时间轴，界面复杂度明显上升。

3

生成后草稿去向

本图按「标记已生成 + 30 天后清理」。也可以生成成功即删除草稿，或自动转成项目备注，需定一条。

4

是否需要独立管理页

Popover / Sheet 内已可完成全部操作。若草稿常超过 20 条，建议再加一个「全部草稿」页面（侧栏 / 项目页入口）承载搜索与批量管理。
