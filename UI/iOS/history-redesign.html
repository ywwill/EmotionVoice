历史记录（项目页）优化设计

现状是一张按创建时间倒序平铺的等权列表：看不出日期、搜索只覆盖已加载的名称、点行即播放并跳详情、删除不可挽回。本稿给出新的信息架构、时间分组、行卡片、播放与删除流程，色板与组件沿用 Aurora Pop，深浅两套主题同步给出。

01为什么要改 · 七个现状痛点

对照 ProjectsView.swift / HistoryViewModel.swift 与 10-27 总设计稿第 5 章。每条都给出对应的界面改动，不只是换皮。

P1 · 信息架构

没有时间锚点

列表平铺等权，meta 只有「音色 · 时长 · 大小」，创建日期完全不可见，翻到第 3 页就找不到"上周那条"。
按 今天 / 昨天 / 本周 / 更早 分组，组头吸顶并带条数；行内右上角补时间（时分 / 昨天 / 日期）。
P2 · 搜索

搜不到，也不敢搜

.searchable 只匹配 shownName，且只在已分页加载的数据里过滤 —— 老记录根本不在内存里。
改走 全库检索，范围覆盖 名称 / 原文 / 音色，命中词高亮，结果按分组展示并显示「共 N 条」。
P3 · 播放

试听成本过高

点任意行 = 立即播放 + push 播放详情；想连着听几条要反复返回，列表里没有暂停/切换。
行内 32pt 播放按钮 就地试听；底部 常驻 mini player 跨页保留；点击行才进详情。
P4 · 删除

一次误触就永久没了

左滑删除 → alert 确认 → 磁盘文件 + 库记录一并抹掉，没有撤销、没有回收站。
改为 移入最近删除（保留 30 天）+ 删除后 5 秒撤销 Toast；最近删除页可恢复 / 彻底删除。
P5 · 状态

异常记录不说话

生成中 / 失败 / 文件已丢失在列表里没有任何反馈，用户只会看到一条"点了没反应"的行。
行内 状态胶囊 + 进度条 / 重试按钮；文件丢失置灰并标注「文件已丢失」，不允许播放。
P6 · 操作

图标猜谜 & 批量能力弱

左滑三连纯图标；多选工具条只有分享/删除两个图标，导出与复制藏得太深。
批量条改 图标 + 文字，补 导出 / 复制 / 收藏；多选态导航栏显示「已选 N 条」。
P7 · 空态

空页面不告诉用户下一步

只有一行灰字「还没有生成的音频」，没有入口、没有引导。
插画 + 一句说明 + 「去创作」主按钮；搜索无结果时补「换个关键词 / 清除筛选」。

02主视觉 · 默认列表

一屏之内同时给到「总量 → 筛选 → 时间定位 → 单条信息 → 试听 → 当前播放」。大标题改为「历史记录」，标签栏仍沿用「项目」，是否同步改名列为待确认项。筛选胶囊只保留「全部 / 收藏」，行卡片不再显示情绪。

05交互与动效规则

沿用项目里已经踩过坑定下来的规则，新方案不推翻它们。

播放：行内试听 ≠ 进详情点 32pt 播放按钮就地播/停，不 push；点行才 router.push(.player)。mini player 常驻且跨标签保留，展开才进详情。playingKey 继续用 identifier 判等。
删除：软删 + 5s 撤销确认后立刻从数组移除并出 Toast；5 秒内不许动磁盘文件；点撤销清 deleted_at 并把行插回原位置（纯插入，不做 remove+insert）。倒计时结束才落盘清理。
磁盘 IO 在动画事务之外复制 / 删除 / 重命名继续遵守现有约定：withAnimation 里只有一次数组写入，磁盘操作走 Task.detached 或事务之前完成。
列表刷新用可动画属性筛选 / 搜索变化后 ScrollView.id(scrollResetID) 重建复位滚动，过渡靠 opacity + offset，不用容器 .transition；节奏沿用 0.1s 淡出 → 换数据 → 0.28s 淡入。
搜索：回车立即查，滚动收键盘.submitLabel(.search) + @FocusState，提交时取消防抖立即查全库；.scrollDismissesKeyboard(.immediately) 挂在 ScrollView 本身并补拖拽兜底。
分页：先写本地 page 再同步沿用音色库踩过的坑：上拉追加必须先写本地 page 再 syncToVM()，空页回退 page = max(1, next-1)；分组头按合并后的数据重算。
键盘与底栏避让本页没有文本编辑区，但多选工具条 / mini player 仍挂在 safeAreaInset；搜索框聚焦时键盘弹出，工具条需要按现有「键盘顶边」逻辑上移，别压到键盘。
同一层只挂一个 .alert删除确认、清空最近删除、清空文本三个入口互斥；重命名继续用自绘 RenameDialog，不退回系统 Alert 的 TextField。
收藏：单点写入 + 跨页同步播放详情页右上角心形、列表左滑、多选工具条三处共用同一个 AudioFlagStore（独立轻量存储，按 audio id 索引），不要用各自 View 的本地 @State；任一处切换后，列表角标 / 「收藏」计数 / 「仅看收藏」结果同时刷新。取消收藏的处理沿用音色库 VoicesLibraryView.toggleFavorite 的既有规则。
最近删除：入口固定在 ⋯ 菜单导航栏右上角「⋯」→ 菜单第一项「最近删除」（带条数 badge），点进 push 最近删除页；不放进筛选胶囊行，避免被当成另一个筛选维度。删除后的撤销 Toast 只负责撤销，菜单 badge 随软删记录实时变化。

06需要你拍板的 7 件事

这些是会动到数据层 / 全局文案的决策，先确认再落代码。

D1
页面与标签是否改名

设计稿用「历史记录」作大标题、标签栏仍是「项目」。若要把标签也改成「历史」，需要同步改 TabRouter.Tab.title 和三语 .strings；不改的话只动 navigationTitle。

D2
最近删除保留多久 · 状态存哪里

稿里写 30 天，也可退化成「手动清空、不自动过期」。⚠️ 当前 createTables() 是 create(ifNotExists: true)：给旧库加列不会生效（不会自动 ALTER），项目也约定不做迁移。推荐把 deletedAt 与 isFavorite 一起放进独立轻量存储（UserDefaults / JSON，按 audio id 索引），完全不动 audio_items 表；若坚持入库，需要启动时读 PRAGMA table_info 显式 ALTER，且不能走 DROP 重建（会丢已有音频记录）。

D3
全库搜索的落地范围

名称 / 文案 / 音色三字段全库检索要改 ProjectService 的查询与 HistoryViewModel 的分页模型（搜索态不再分页）。若想先做轻量版，可只保留「名称 + 音色」的本地过滤。

D4
收藏状态的数据来源

音频表目前没有 is_favorite 列（只有音色表有），收藏是音频条目的新属性。推荐与 D2 共用同一份独立轻量存储；筛选「收藏」时计数恒为全量、与「全部」单选互斥。情绪不显示、也不存，生成时保存的语气标记无需为列表派生任何 UI 文案。

D5
mini player 与后台接收浮条的层级

两者都想占标签栏之上同一位置。稿里建议互斥：生成中且弹窗关闭时显示后台浮条，否则显示 mini player；不叠放。需要确认这个优先级。

D6
最近删除入口：⋯ 菜单 还是 筛选行末尾

稿里主推导航栏右上角「⋯」菜单第一项（带条数 badge，见屏 I），不占筛选行、不与胶囊混淆；备选是把「最近删除 ›」做成筛选行右端的固定文字链（更好发现，但会挤横向空间、视觉上像第三个筛选条件）。二选一后我再定稿。

D7
收藏入口范围：只做播放页 / 只做列表 / 两处都做

我建议两处都做：播放详情页右上角常驻心形是主入口（听完即收藏，改动最小），列表左滑 + 多选工具条是辅助批量入口，两者共用同一个 store 同步（见屏 J / C / F）。若想先减负，第一期只做播放详情页即可。
